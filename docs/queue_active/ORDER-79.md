# Active Queue Spec: ORDER-79

> Canonical status and execution order are indexed in `docs/CODEX_QUEUE.md`.

#### [~] ORDER-79 [P0·직관성] 계획판 설명과 실제 배치 순서를 `제안→주차`로 맞춘다

**사용자 근거 (2026-08-04):** 한 편의 소설·영화라는 기준은 산문만이 아니라
지금까지의 피드백 전체를 가리킨다. 플레이어가 읽은 설명, 화면에서 본 상태,
누른 행동과 그 결과가 서로 다른 말로 움직이면 작품의 신뢰가 첫 계획부터
깨진다. 사용자가 별도 결정을 내려야 하는 새 규칙이 아니라, 이미 튜토리얼이
약속한 조작을 실제 계획판이 지키게 하는 기존 기능 수리다.

## 현재 모순

- 튜토리얼은 `제안을 고른 뒤 넣을 주를 선택하세요 / Choose an offer, then
  choose its week`라고 설명한다.
- 실제 UI는 제안 버튼을 누르는 순간 현재 선택 주차 또는 첫 빈 주차에 즉시
  배치하고, 주차 버튼은 선택 표시만 바꾼다.
- 따라서 플레이어가 읽은 인과와 실제 입력의 인과가 반대다. 첫 달부터
  “내가 어느 주를 골랐는가”보다 “게임이 어디에 넣었는가”를 해석하게 만든다.

## 깊이 3문

1. 지우면 튜토리얼과 실제 조작이 다시 반대로 움직여 첫 계획의 신뢰가 깨진다.
2. 제안은 의도, 주차는 확정이라는 두 단계가 월간 시간 배분의 핵심 선택을
   플레이어에게 돌려준다.
3. 일정·효과·수치를 건드리지 않고 입력 한 번당 상태 변화의 의미만 바로잡을 수 있다.

## 배치 A — 한 가지 보이는 상태, 한 가지 확정 동작

- 제안에 포커스하거나 마우스를 올리면 상세만 바뀐다. 배치 대기 상태나 일정은
  바뀌지 않는다.
- 제안 버튼을 누르면 그 제안이 **배치 대기**가 된다. 이 시점의 일정 snapshot은
  누르기 전과 바이트 의미상 같아야 한다.
- 이미 대기 중인 같은 제안을 다시 누르면 일정은 그대로 두고 대기만 취소한다.
  이것이 미확정 의도를 버리는 명시적인 탈출구다.
- 대기 상태는 색만으로 알리지 않는다. 제안 카드와 안내 문구가
  `선택됨 · 넣을 주를 고르세요 / SELECTED · CHOOSE A WEEK`를 함께 보여 준다.
- 대기 중 합법적인 주차를 누르면 그때 정확히 한 번 배치한다. 성공 뒤 대기
  상태를 비우고, 일정에는 대상 주차 한 곳만 달라져야 한다.
- 대기 없이 주차를 누르면 주차 선택과 상세만 바뀌며 일정을 수정하지 않는다.
  이미 배치된 주는 그 제안의 상세를, 빈 주는 먼저 제안을 고르라는 안내를 보인다.
- 이미 배치된 제안을 다시 누르면 같은 대기 상태로 들어가고, 다른 합법 주차를
  눌렀을 때 기존 주차에서 새 주차로 한 번 이동한다. 복제하지 않는다.
- 다른 제안이 이미 든 주차를 누르면 기존 약속을 조용히 지우거나 맞바꾸지 않는다.
  `먼저 그 주의 약속을 빼세요 / REMOVE THAT COMMITMENT FIRST`를 보이고 대기를
  유지한다. 이미 그 제안이 놓인 같은 주차를 누르면 일정은 그대로 두고 대기만
  끝내며, 성공한 이동으로 허위 집계하지 않는다.
- 고정 일정은 지금처럼 `고정 일정 / FIXED EVENT`로 표시한 비활성 슬롯이라
  진입 자체를 막는다. 기한 밖 주차는 배치하지 않고 눈에 보이는 실패 이유를
  남기며, 대기 의도는 유지해 플레이어가 다른 주를 고를 수 있게 한다.
- 월을 새로 열거나 읽기 전용으로 열 때와 일정 탭을 떠날 때는 숨은 대기를
  지운다. 대기 중에는 검토 단계로 들어갈 수 없고, 같은 제안 재입력으로 먼저
  취소할 수 있다. West로 일정 하나를 뺄 때는 그 제거만 수행하고 대기는 유지한다.
- 일정 제거, 두 단계 검토·확정, 읽기 전용 재열기, 루틴 선택, 세로 연락폰,
  키보드·패드 취소 규칙은 그대로 둔다. 일정 제거 뒤에도 숨은 자동 재배치는 없다.
- 테스트용 `assign_offer_to_week()` 직접 API는 컴포넌트 fixture에 남길 수 있지만,
  제품 UI와 실제 입력 완주 경로는 반드시 제안 누르기→주차 누르기를 거친다.

## 검증

- 포커스·hover·제안 누르기 직후 일정 불변, 대기 표면 노출, 같은 제안 재입력의
  대기 취소와 일정 불변을 KO/EN에서 확인한다.
- 대기 없는 주차 입력은 0 delta, 합법 주차 입력은 exact one-slot delta와 대기 해제,
  이동은 old erase + new insert 한 쌍임을 확인한다.
- 이미 찬 주차와 기한 위반은 0 delta·보이는 오류·대기 유지, 같은 제안의 기존
  주차는 0 delta·대기 해제다. 고정 일정은 보이는 비활성 슬롯과 0 delta다.
  읽기 전용 계획은 제품 입력과 직접 API 어느 경로에서도 바뀌지 않는다.
- 첫 진입 3장 튜토리얼은 계획 mutation 0을 유지한다. 그 뒤 실제 계획 한 건을
  설명 순서로 만들어 제품 행동과 문구를 함께 확인한다.
- KO South와 EN 키보드 24주 자동 완주는 여섯 달 모두 `offer→week` 순서로
  수동 슬롯 22개를 계획하고 `offer_intents=22`, `week_commits=22`와 기존 최종
  상태·First Bill·현수·단일 저장·CTA 결과를 그대로 만든다.
- 첫 계획의 대표 경로는 안정 메타데이터 직접 포커스 없이 raw 방향 이벤트로
  제안→주차 포커스 연결을 건너 정확한 두 버튼에 도달한다. 이 자동 연결 검증과
  실물 패드 손맛의 사람 판정을 같은 것으로 보고하지 않는다.
- 제안·주차 두 열의 좌우 이웃과 각 열의 상하 이웃을 명시해 Godot의 화면 기하
  추정에 맡기지 않는다. 대기·기한 오류의 긴 한영 문구는 1280×800과 960×600에서
  카드·상태·하단 힌트 잘림이 없는지 확인한다.
- 표적 검사, 전체 감사, 두 실제 입력 스코프와 CI를 모두 통과한다.
