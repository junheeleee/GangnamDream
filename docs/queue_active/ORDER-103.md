# Active Queue Spec: ORDER-103

> Canonical status and execution order are indexed in `docs/CODEX_QUEUE.md`.

#### [~] ORDER-103 [P0·플레이 표본] M01~M06 월간 약속을 직접 고르는 독립 체험판을 만든다

**사용자 승인 (2026-08-15):** 형식적인 순서 맞추기가 아니라 실제로 무엇을
지키고 무엇을 놓칠지 고민하게 만들어야 한다. ORDER-102의 M01~M06 전략 증명이
끝났으므로 이제 그 규칙을 직접 눌러 보고 판단할 수 있는 작은 실물을 만든다.

**사용자 1차 판정 (2026-08-15):** “스포일러로 놓치면 어떤 효과가 있는지를
알려주면 재미없잖아.” 선택 전 카드가 정확한 후속 사건·관계 단계·닫힐 문을
설명한 표면은 반려한다. 알려야 할 것은 행동·축·마감과 미룸/만료 규칙이고,
실제 결과와 먼 후속은 일어난 뒤에만 드러난다.

## 깊이 3문

1. 지우면 60개월 표는 다시 문서 속 가능성에 머물고, 같은 축 여유·미룸·문 닫힘이
   플레이어에게 고민으로 읽히는지 판정할 수 없다.
2. 기존 24주 숫자 여력 판과 저장을 바로 교체하면 새 규칙의 재미와 이관 버그를
   구분할 수 없다. 이번 표본은 별도 장면·별도 자동저장으로 격리하고 기존 판은
   읽거나 덮어쓰지 않는다.
3. 첫 여섯 달만 완전하게 고른다. 주력과 함께 약속의 역할, 같은 축 여유, 한 번의
   미룸, 사람 focus, 다음 달 대가가 보이면 충분하다. 기존 사건 재생·240주 이관·
   정식 메뉴 진입은 사람 판정 뒤의 별도 오더다.

## 배치 — 플레이 가능한 6개월 표본 12단위

1. `story_map`의 M01~M06만 읽고 다른 월을 실행하지 않는다.
2. 시작에는 여유가 없고 주력 하나만 고른다.
3. 전월에 만든 같은 축 여유가 있을 때만 `함께` 하나를 더 고르며 확인 즉시 쓴다.
4. 주력 하나만 완료하면 다음 달 같은 축 여유를 만든다. 빚·압력을 갚은 주력과
   둘을 끝낸 달은 새 여유를 만들지 않는다.
5. 미룸은 다음 달 후보로 정확히 한 번 돌아오고 다시 놓치면 만료된다.
6. 만료는 카드가 선언한 특정 문·압력만 닫고 숨은 전역 벌점을 쌓지 않는다.
7. 주력/함께는 클릭 선착순이 아니라 명시 역할이다. 같은 두 장을 어떤 순서로
   눌러도 확인 payload와 결과 원장은 같다.
8. M03에서 다은·지연을 함께 지키면 주력 인물이 M05의 연락과 M06의 약속까지
   같은 사람으로 이어진다.
9. 카드 앞면은 구체 행동·축·마감과 `다음 달 한 번 돌아옴 / 이번 달 기한`만
   보여 준다. 정확한 완료 이득, 놓쳤을 때 닫힐 사건·인물 경로, 내부 token ID,
   AP 숫자·선악 점수는 선택 전에 노출하지 않는다.
10. 월 확인 뒤 결과와 다음 달 여유/빚/닫힌 문을 한 화면에서 설명한다.
11. 매달 확인 직후 이 체험판 전용 파일에 자동저장하고, 이어하기·처음부터를
   제공한다. 기존 retail/V2 save path와 namespace는 사용하지 않는다.
12. M06 뒤에는 여섯 달의 주력·함께·미룸·닫힌 문을 비교 가능한 회고로 보여 준다.

## 제품·UI 경계

- 독립 `StoryMapM1M6Playtest` 장면을 직접 실행한다. `StartMenu`, `MainGame`,
  `DemoCoreLoopV2`, `StoryMode`, `GameState`, `SaveManager`, 기존 24주 장면과
  `project.godot`은 수정하지 않는다.
- `SeoulCycleBoard`의 숫자 타일은 재사용하지 않는다. 기존 카드 화면의 글꼴·패널·
  패드 의미 입력을 시각 참고로만 쓰며 새 화면이 주력/함께를 직접 소유한다.
- 한국어·영어, 마우스·키보드·패드, 960×600과 1280×800에서 같은 정보를 제공한다.
- 같은 주 마감은 여유가 시간을 복제한다는 뜻이 아니다. 카드가 정확한 동시각
  배타를 선언하지 않는 한, 여유는 그 주에 둘을 끝낼 준비와 비용을 뜻한다.

## 완료 증거

- M01~M06 여섯 달을 새 시작→자동저장→이어하기로 끝까지 진행한다.
- M01 둘째 거부, 같은 축/다른 축 판정, 여유 소모와 무환급, 빚 상환 뒤 무여유,
  deferred 1회→expired, M03→M05→M06 인물 동일성을 표적 검사한다.
- 같은 `{주력, 함께}`는 클릭 순서와 저장 왕복 뒤 byte-equivalent 결과를 만든다.
- 기존 W24 종료 fixture와 retail/V2 저장 파일은 실행 전후 byte-equivalent다.
- KO/EN과 960×600·1280×800에서 카드 상세·포커스·확인/취소가 잘리지 않는다.
- 표적 Godot 검사 목표 5초 이하. `story_map` 정적 검사와 diff-check만 추가하고
  전체 감사·240주·거대 V2 검사는 실행하지 않는다.

## 사람 판정

기계 GREEN은 재미 GO가 아니다. 사용자가 M01~M06을 직접 플레이한 뒤
`주력과 함께의 차이를 이해했는가`, `항상 둘째가 정답처럼 느껴지는가`,
`한 번은 실제로 무엇을 버릴지 고민했는가`, `닫힌 문이 벌점이 아니라 자기 경로로
느껴지는가`를 판정한다. 이 합격 전에는 기존 24주 판에 이관하지 않는다.

## 현재 증거 (2026-08-15)

- **L1 기계 완료:** 전용 검사는 M01~M06 완주, 같은 축 여유, 둘째 무환급,
  부담 상환, 미룸 1회, M03→M05→M06 인물, 저장 왕복, 재확정 무변경과 UI
  흐름을 5초 이내에 검증한다. KO/EN 여섯 달의 선택 전 가시 텍스트에서 작가용
  contract와 정확한 완료·놓침 preview가 0인지도 확인한다. 결과는 `months=6
  margin=4 deferred=2 actor=2 save=2 ui=1 disclosure=2`다.
- **L2 자가 완료:** KO/EN, 960×600·1280×800에서 스포일러 없는 선택 표면과
  결과·회고를 직접 렌더하고 여섯 달을 완주했다. M03 다은 주력+지연 함께에서
  다은 focus가 M05·M06까지 이어지고 완료 저장의 이어하기가 회고로 복귀한다.
- 체험판은 별도 프로젝트·전용 자동저장만 사용한다. 기존 `project.godot`, 메뉴,
  24주 런타임, `GameState`·`SaveManager`와 retail/V2 저장은 수정하지 않았다.
- **L3 재판정 대기:** 1차 반려된 정확한 완료·놓침 효과와 미래 문을 선택 화면에서
  제거한 `.2` 체험판을 만들었다. 사용자가 다시 플레이해 고민과 호기심을
  판정하기 전까지 상태는 `[~]`이며, 기존 데모 이관도 시작하지 않는다.
