# Active Queue Spec: ORDER-64

> Canonical status is indexed in `docs/CODEX_QUEUE.md`.

#### [ ] ORDER-64 [P1·서명] 개성은 그리는 것이 아니라 되풀이하는 것이다

**사용자 결정 (2026-07-30):** 외주 0원. 인물 디자인도 작곡도 사지 않는다.
근거는 `DECISIONS.md` 2026-07-30 항목이 소유한다.

**그래서 이 오더가 존재한다.** 생성 자산의 문제는 못 그리는 것이 아니라
평균을 그리는 것이고, 평균은 돈이 아니라 규율로 이긴다. 팬이 인물을
알아보는 근거는 렌더 품질이 아니라 **같은 소품이 매번 그 자리에 있다는
사실**이다.

## 착수 전 이미 나온 증거

`IP_VISUAL_IDENTITY.md`에 주연 6인의 서명표가 **이미 완성돼 있다** — 인물마다
고정 실루엣, 시그니처 재질, 소유 소품, 오디오 모티프. 전문 수준이다.

| 명세 | 실제 |
|---|---|
| 6인 서명표 | **이 문서를 읽는 검사 도구가 0개.** 참조처는 `context_manifest.json`(분류)뿐 |
| 6인 오디오 모티프 | 실존 BGM은 지연·다은·현수뿐. **민준·재혁·상철·아버지 0** |
| 민준 `4음 테마` | **존재하지 않는다.** 그런데 아버지 모티프는 *"민준의 4음 테마에서 마지막 음이 빠진 것"*으로 정의돼 있다 |
| `AudioAssetCheck.gd`의 모티프 명단 | `family/survival/hyunsu/ambition/daeun/jiyeon` — **IP 정본의 6인과 인물 집합이 다르다** |
| 소유 소품(다은 머리핀, 지연 차 키, 상철 명함, 아버지 23초 통화 화면) | 비주얼 바이블에 산발적으로 있으나 **되풀이를 강제하는 검사 없음** |

마지막 두 줄이 이 오더의 핵심이다. **두 정본이 서로 다른 인물을 모티프
주체로 보고 있고, 없는 테마의 결손으로 정의된 모티프가 있다.**

---

## 1. 배치 1 — 서명표를 기계 판독으로 승격

`content/meta/identity_signature.json`을 만든다. **내용을 새로 발명하지
않는다.** `IP_VISUAL_IDENTITY.md`의 표를 그대로 옮긴다.

```
인물 | 고정 실루엣 | 시그니처 재질 | 소유 소품 | 오디오 모티프 | 최소 되풀이
```

- 산문 정본은 계속 `IP_VISUAL_IDENTITY.md`가 소유한다. JSON은 **검사용
  투영**이며 두 곳이 어긋나면 산문이 이긴다.
- 옮기는 중 표에 없는 값을 채워 넣지 않는다. 빈 칸은 빈 칸으로 둔다.
  **빈 칸을 발견하는 것이 이 배치의 산출물 절반이다.**

## 2. 배치 2 — 검사 `tools/identity_signature_audit.py`

| 검사 | 내용 |
|---|---|
| 소품 되풀이 | 각 인물의 등록 자산 중 소유 소품이 명시된 비율. 래칫 |
| 소품 배타 | 한 인물의 소품이 다른 인물에게 재할당되지 않았는가 |
| 실루엣 게이트 | 등록 초상이 64px에서 구분되는가 (`IP_VISUAL_IDENTITY` 게이트 1) |
| 모티프 존재 | 서명표의 모든 모티프가 실제 오디오 키로 존재하는가 |
| 명단 정합 | `AudioAssetCheck.gd`의 명단과 서명표 명단이 일치하는가 |
| 장면 소유 | 각 주연이 다른 인물로 대체 불가능한 장면을 최소 하나 갖는가 |

`audit_scope.json`에 등록한다. **실루엣 게이트는 자동 판정이 어려우므로,
자동으로 못 재는 항목은 사람 판정 대기로 표시하고 통과 처리하지 않는다.**

## 3. 배치 3 — 모티프 정합 수리

**순서가 있다. 민준의 4음 테마가 먼저다** — 아버지 모티프가 그것의 결손으로
정의돼 있어서, 민준 테마 없이 아버지 모티프를 만들면 정의가 성립하지 않는다.

1. 민준 4음 테마를 만든다. 맑음·왜곡·공동(空洞) 세 변형을 갖는다.
2. 아버지 모티프 = 그 테마의 마지막 음이 빠진 형태.
3. 재혁(마른 핑거스냅/셔터 트랜지언트), 상철(낮은 브러시 리듬 + 뮤트 브라스
   한 호흡)을 채운다.
4. `AudioAssetCheck.gd`의 `STORY_MOTIF_KEYS`와 서명표 명단을 일치시킨다.
   **어느 쪽을 정본으로 삼을지는 판단이므로 근거를 적고 한쪽으로 모은다.**

출처 규율은 그대로다 — **실제 녹음·실악기 샘플만.** 코드 파형·오실레이터·
생성 노이즈·런타임 합성은 금지다(`DECISIONS.md` 2026-07-23).

## 4. 배치 4 — 음색 팔레트 확장

BGM 20곡이 전부 Salamander 피아노 단일 음색이다. 출처 규율은 지켰지만
**팔레트가 하나라서 20곡이 한 곡처럼 들린다.** 사용자가 물은 "따로 찾아
들을 만한가"에 걸리는 지점이 여기다.

- CC0·CC BY 실악기 샘플 라이브러리를 조사해 **2~3 음색을 더한다.**
  현악 하나, 기타/플럭 하나, 방 울림이 있는 저역 하나 정도.
- 라이선스는 `AUDIO_SOURCE_MANIFEST.json`의 기존 형식으로 기록한다.
  출처·SHA-256·라이선스·편집 이력을 빠짐없이 남긴다.
- **곡을 새로 늘리지 않는다.** 기존 20곡의 편성을 다시 하는 작업이다.
  모티프 규율(메인 테마 한 줄이 인물 곡마다 변형되어 나타난다)이 곡 수보다
  먼저다.

## 5. 배치 5 — 채택률 규율

**0원으로 생성 자산의 평균성을 이기는 유일한 레버다.** 잘 뽑는 것이 아니라
많이 뽑고 대부분 버리는 것이다.

`ART_MASTER_PRODUCTION.md`의 `Rejected Trials`와 `art_master_manifest.json`의
기각 후보 기록은 이미 업스케일 파이프라인에 존재한다. **그 개념을 신규
자산 전반으로 올린다.**

| 자산 | 최소 후보 | 채택 |
|---|---:|---:|
| 배경 | 8 | 1 |
| 초상 | 12 | 1 |
| 키 비주얼·주요 CG | 24 | 1 |

- 기각 후보와 **기각 사유**를 원장에 남긴다. 사유 없는 채택은 채택이 아니다.
- 후보는 Godot 프로젝트 밖 시스템 임시 폴더에만 생성한다
  (`PRODUCTION_ASSET_PIPELINE.md`가 이미 정한 규칙).
- 채택본은 `ART_AI_AUDIT.md` 방식으로 **사람 판정 + 파일 해시 고정**한다.
  사람의 판정은 한 번, 기계의 수호는 영원히.

## 6. 금지·보존

- `IP_VISUAL_IDENTITY.md`의 서명표를 이 오더에서 고치지 않는다. 옮기고
  강제할 뿐이다. 표가 틀렸다고 판단되면 별도 오더로 올린다.
- 서명 강제를 이유로 기존 자산을 재생성하지 않는다. 이 오더는 **검사와
  기준선**을 세우고, 실제 교체는 그 목록에서 나온 별도 오더가 한다.
- 인물을 늘리지 않는다. 주연 6인 밖으로 서명을 확장하지 않는다.
- 자동으로 못 재는 항목을 통과 처리하지 않는다. 사람 판정 대기로 남긴다.
- 저장 호환, 엔딩 ID, 사용자 소유 `project.godot`을 건드리지 않는다.
