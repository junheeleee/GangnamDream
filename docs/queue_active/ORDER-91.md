# Active Queue Spec: ORDER-91

> Canonical status and execution order are indexed in `docs/CODEX_QUEUE.md`.

#### [ ] ORDER-91 [P0·코어 표면] 계획판 카드를 목록 항목이 아니라 출처가 있는 물건으로 만든다

**사용자 승인 (2026-08-05):** `docs/PROPOSALS.md`의 `P-13`(출처)과 `P-15`(연출)을
하나로 묶어 실행한다. 사용자가 설계를 위임했고, 두 건이 같은 하나의 문제라는
것이 설계 과정에서 드러났기 때문이다.

**설계 한 문장:**

> 계획판의 카드는 목록 항목이 아니라 **민준의 수첩에 어떻게든 들어온 물건**이다.

`P-13`(출처가 안 보인다)과 `P-15`(밋밋하다)는 따로 고칠 두 결함이 아니다.
**카드가 어디서 왔는지를 형태로 보여 주는 순간 둘 다 풀린다.** 출처는 정보이자
동시에 물성이다 — 문자는 문자처럼 생겼고 메모는 손글씨처럼 생겼다.

**참조 (정본: `docs/DECISIONS.md` 2026-08-05):**

- **Disco Elysium** — 일지의 모든 과제에 누가 언제 준 것인지가 남는다
- **Citizen Sleeper** — 모든 노드가 만난 사람·가 본 장소에 붙어 있고,
  **상태를 글자가 아니라 형태로** 구분한다
- **Papers, Please** — UI가 서류 폼인데 게임스럽다. 대형 모션이 아니라
  질감·소리·물성이 그것을 만든다
- **Cultist Simulator** — 카드가 테이블 위에 있다는 물성이 서사를 만든다

원리: **연출은 애니메이션이 아니라 물성이다.** 외주 0원에서 유일하게 갈 수 있는
길이며, 위 세 작품 모두 대형 모션 예산 없이 성립한다.

**현재 실측:**

- 카드 문자열은 `[상태] · [상태] · 종류 · 제목 \n 기한`이다
  (`scenes/CoreLoopPlanner.gd:880-885`). **읽어야 할 이름이 네 번째 조각**이고
  앞의 셋은 전부 상태·분류다.
- 고를 수 있는 51개 중 **29개는 데이터가 출처를 알고 있다**
  (`self_note` 23 · `inbound_message` 4 · `call_log` 1 · `world_encounter` 1).
  화면은 하나도 쓰지 않는다.
- **22개는 데이터에도 출처가 없다.** 첫 달에 처음 보는 것들이 거기 있다 —
  `미래산업기술 채용 공고`, `목요일 밤 대타`, `자기소개서 네 문항 고쳐 쓰기`,
  `휴대폰을 끄는 일요일`.
- 씬 21개 중 **17개가 `create_tween`을 쓰는데 계획판은 0**이다.
  `AudioManager` 호출은 **1회이며 그것이 닫을 때**다(`:182`).
  StoryMode는 20회, MainGame은 55회다.
- 배경 `gangnam_night_street.png`를 깔고
  `modulate=(0.34,0.37,0.43,0.34)` 뒤 `#07090c`를 0.66 알파로 덮는다.
  원본이 화면에 남기는 몫은 `0.34 × (1 − 0.66) ≈ 0.116`이고 RGB도 이미
  0.34~0.43으로 눌려 **대략 4%**다.
- 패널은 전부 `StyleBoxFlat`(단색 + 1~2px 테두리 + 6px 라운드, `:2571-2581`).
  그림자·질감·계층이 없다.

**새로 찾은 정본 위반:** 확정본 표면이
`지난달에 고르지 않은 제안`(`LEFT OUT LAST MONTH`)을 **목록으로 통보한다**
(`:1268-1273`). `docs/CORE_LOOP_V2.md` §4 `놓친 것은 알림이 아니라 흔적으로 온다`가
*"목록 화면은 최후 수단이다. `지난달 기록` 같은 정리 표면으로 놓침을 통보하면
게임이 먼저 말하는 것이고, 플레이어는 발견하지 못한다"*고 금지한 바로 그 형태다.
**이번 달 확정 직전에 보이는 `고르지 않은 제안`은 유지한다** — 그것은 지금 내리는
결정의 대가이지 과거 통보가 아니다.

**착수 때 잠글 파일 후보:** `scenes/CoreLoopPlanner.gd`,
`content/meta/demo_core_loop_v2.json`(출처 없는 22개), 대응 영어 오버레이,
카드 질감·배경을 소유한 자산 원장과 `assets/` 경로,
`AudioManager` 큐 원장, `docs/CORE_LOOP_V2.md` §5, `docs/QA_CHECKLIST.md`,
`docs/WORK_LOG.md`, 큐 활성·아카이브 경로. 착수 선언은 실제로 만지는 파일만
남겨 별도 커밋으로 만든다.

**선행 조건:** `ORDER-89`가 닫힌 뒤에 착수한다. 레일·탭 구조가 확정되기 전에
카드 레이아웃과 물성을 올리면 두 번 일한다.

## 깊이 3문

1. 이 설계를 지우면 계획판은 계속 폼으로 읽히고, 사용자 판정
   *"이 안에서 모든 게임성이 다 나와야 하는데 지금은 제일 약점"*이 그대로
   남는다. 데모에서 가장 오래 보는 화면의 첫인상이 곧 리뷰의 첫 문장이 된다.
2. 이 작업은 선택 구조·효과·저장·확정 조건을 바꾸지 않는다. **같은 입력은 같은
   결과를 낳아야 하며**, 바뀌는 것은 카드가 무엇을 보여 주는가와 어떻게 생겼는가다.
3. 출처를 채우는 것은 콘텐츠 작업이므로 전량 22개를 한 번에 하면 다른 오더를
   밀어낸다. **첫 달 4개로 실측하고 나머지는 그 결과로 정한다** — 첫인상을
   결정하는 것은 첫 달이고, 4개국어 번역 착수 전에 끝나야 두 번 번역하지 않는다.

## 배치 A — 카드가 출처를 먼저 말한다

- 카드 읽기 순서를 **`누가·어디서` → `무엇을` → `언제까지`**로 바꾼다.
  현재의 `[상태]·[상태]·종류·제목·기한` 순서를 버린다.
- **상태는 글자가 아니라 형태로 표시한다.** `선택 중`·`일정에 넣음` 두 문자
  라벨을 없앤다. 배치된 카드는 주차 칸으로 옮겨 가 제안 목록에서 빠지므로
  목록에 남아 있다는 것 자체가 `아직 안 정함`을 뜻한다.
- `phone_surface`별로 카드가 다르게 생긴다. 네 형태를 넘기지 않는다.

  | 출처 | 카드가 말하는 것 | 형태 |
  |---|---|---|
  | `inbound_message` | 보낸 사람 이름이 가장 먼저 | 문자 조각 |
  | `call_log` | 누구와의 통화에서 나왔는지 | 통화 기록 한 줄 |
  | `self_note` | 민준이 스스로 적었다 | 손글씨 메모 |
  | `world_encounter` | 어디서 마주쳤는지 | 전단·명함 |

- 종류 라벨(`ORDER-90`이 정리한 여섯)은 **출처 다음**으로 물러난다.
  분류보다 출처가 먼저 읽혀야 한다.

## 배치 B — 출처 없는 22개 중 첫 달을 채우고 물성을 올린다

- **첫 달 4개**에 `phone_surface`와 필요한 `message_sender`를 부여한다.
  나머지 18개는 이 배치의 결과를 보고 별도 오더로 정한다.
  **없는 인물·직업·관계·장소를 발명하지 않는다** — 기존 인물과 이미 성립한
  장소만 쓴다.
- **배경을 복원한다.** 현재 약 4%인 기여도를 실제로 읽히는 값으로 올리고,
  본문 대비가 접근성 기준을 지키는 선에서 KO/EN 960×600·1280×800 모두에서
  실측해 고정한다.
- **깊이를 준다.** 수첩 페이지로 읽히도록 종이 질감·그림자·계층을 넣는다.
  `StyleBoxFlat` 단색 일변도를 벗어나되 성능 예산을 넘기지 않는다.
- **모션 세 곳만 넣는다.** ① 카드가 주차 칸으로 들어가는 것, ② 단계 전환,
  ③ 확정. 다른 17개 씬의 기존 패턴을 따르고 새 프레임워크를 만들지 않는다.
  동작 줄이기 설정에서는 제자리 표시로 대체한다.
- **소리 세 개만 넣는다.** 고를 때 · 주차에 넣을 때 · 확정할 때.
  **출시 오디오 원음 규칙(실제 현장·사물 녹음 또는 녹음된 실악기 샘플만,
  코드 파형·오실레이터·생성 노이즈·런타임 합성 폴백 금지)을 지킨다.**
  조달이 안 되면 소리는 이 오더에서 빼고 별도 오더로 남기며, **임시 합성음을
  넣지 않는다.**
- `지난달에 고르지 않은 제안` 표면을 제거한다. 놓침은 정본대로 다음 메시지·
  빈자리·달라진 대사로 온다. 이번 달 확정 직전의 `고르지 않은 제안`은 남긴다.

## 비범위

- **확정 조건·선택 구조·효과·플래그·후속·금액·저장을 바꾸지 않는다.**
  진행 표시와 내비게이션은 `ORDER-89`, 표면 라벨은 `ORDER-90`이 소유한다.
- 출처 없는 22개 중 첫 달 4개를 넘겨 채우지 않는다. 새 제안·새 슬롯·새 인물·
  새 장소·새 관계 단계를 만들지 않는다.
- 폰의 구조를 바꾸지 않는다. 폰은 이미 정본대로 대화·연락처만 소유하고
  연락 행동이 계획판 카드로 넘긴다(`MainGame.gd:763-780`).
- 계획판 밖 화면, 24주 밖 표면, 번역 착수, 새 오디오 프레임워크는 하지 않는다.

## 검증과 사람 판정

- L1: KO/EN 실제 입력 24주 완주, 960×600·1280×800 실제 렌더에서 카드 가독성과
  배경 대비 실측, 패드 포커스 순회, W24/W48/W240 저장, 전체 감사와 CI를
  통과한다. **오디오는 합성 폴백이 0인 것을 검사로 잠근다.**
- L2: 같은 입력이 같은 결과를 내는지 전후 비교한다. 선택·효과·플래그·후속·
  금액·주차가 하나라도 달라지면 실패다. 첫 달 4개의 새 출처가 기존 인물·장소·
  시점과 어긋나지 않는지 `story_rules.json`과 교차 재독한다.
- L3: 사용자는 계획판을 열고 ① 각 카드가 **어디서 왔는지** 말할 수 있는지,
  ② 화면이 관리 앱이 아니라 **수첩을 편 장면**으로 읽히는지, ③ 배치할 때
  무언가를 **놓았다는 느낌**이 드는지 판정한다. 자동 초록을 게임스러움의
  합격으로 부르지 않는다.

## 완료 조건

- 모든 카드가 출처를 먼저 말하고, 상태를 글자가 아니라 형태로 표시하며,
  첫 달 4개를 포함해 첫 달 카드 전부가 출처를 갖는다.
- 배경·질감·모션 3곳·소리 3개(또는 조달 실패 시 분리 기록)가 들어가고,
  `지난달에 고르지 않은 제안` 목록 표면이 없다.
- 선택·효과·저장·확정 조건 무변경이 전후 비교로 증명되고, KO/EN 실제 입력·
  화면·24/48/240주·전체 감사·CI가 초록이며, 규범 승격·일회성 판정을 기록한 뒤
  아카이브한다.
