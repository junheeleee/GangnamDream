# WORK_UNIT.md — 작업 단위와 판정 정본

> 이 문서가 **작업을 얼마나 작게 자르고, 무엇을 증거로 삼고, 누가 판정하는지**를
> 소유한다. 큐 운영 절차는 [`CODEX_QUEUE.md`](CODEX_QUEUE.md)가, 장면 계층은
> [`SCENE_TIER.md`](SCENE_TIER.md)가 계속 소유한다.

## 왜 이 규격이 생겼는가

`ORDER-57`은 870줄·범위 확장 20회·6단계로 커졌고 각 단계가 전부 `AUTO PASS`를
받았다. 그런데 아래가 그 스무 번의 통과를 그대로 지나갔다.

- 당시 월별 도달 가능 authored 슬롯 `2/3/3/4/1/1` — 개수 게이트를
  통과시키려다 얕은 사건을 늘릴 위험이 있었고, 현재는 관측값으로만 남긴다
- 생계·성장·회복 축 authored `0/15`
- 체인 시작 사건의 **95%가 1링크**
- 선택 결과문 **중앙값 69자**
- 실제 플레이 타임 10~20분 대 선언 목표 95분

각 단계는 자기 게이트를 통과했는데 **아무도 전체 모양을 보지 않았다.** 오더가
너무 커서 볼 수가 없었다. 단위를 작게 자르는 것은 취향이 아니라 이 사고의
재발 방지다. 분량을 한 번에 처리하면 디테일이 떨어진다.

## 1. 단위

한 단위는 **하나의 판정 가능한 것**이다. 대략 원고 300~800자 또는 파일 1~3개.
이보다 크면 디테일이 떨어지고, 작으면 관리 비용이 산출보다 커진다.

**[첫 실행 재조정]** `300~800자`와 `파일 1~3개`는 실제 배치를 한 번도 돌리지
않고 정한 추정이다. 판정 가능한 단위라는 원칙은 유지하되 숫자는 첫 배치의
반려율로 고친다.

| 작업 종류 | 1단위 |
|---|---|
| 인물 성경 | 인물 1명 (전 칸) |
| 장면 심화 | 장면 1개 (계층 계약 충족까지) |
| 휴면 콜백 부활 | 콜백 1건 (생산자 배선 + 재집필) |
| 챕터 마감 | 4단계 중 1단계 |
| 감사 신설 | 검사 1종 |
| 자산 제작 | 자산 1점 + 계약 배선 |

## 2. 배치

**한 배치는 15~25단위**다. 배치 안의 단위는 **서로 의존하지 않게** 짠다.
하나가 반려돼도 나머지가 무의미해지지 않아야 한다. 의존이 불가피하면 배치를
나눈다.

**[첫 실행 재조정]** `15~25`는 추정이다. 의존 없음이라는 원칙은 유지한다.

## 3. 단위마다 세 관문

### ① 착수 전 — 깊이 3문

답하지 못하면 착수 금지다.

1. **이걸 지우면 다른 무엇이 깨지는가?** — 아무것도 안 깨지면 장식이다.
2. **고른 플레이어와 안 고른 플레이어의 상태가 24주 뒤에 다른가?** — 같으면
   선택이 아니다.
3. **같은 자리에서 무엇과 경쟁하는가?** — 경쟁이 없으면 배분이지 결정이 아니다.

이 셋은 위 실측 결함 전부를 사전에 잡았을 질문이다. 생계 카드는 1번에서,
20주 유혹 1회는 3번에서 걸렸을 것이다.

### ② 완료 시 — 증거 양식

**산문 금지.** 측정값 또는 `file:line`만 쓴다. 한 칸이라도 비면 완료 선언
금지다. `구현했다`는 증거가 아니다.

```
도달 경로      : <실행한 시뮬/검사 출력 원문>
생산자 ↔ 독자   : <file:line> ↔ <file:line>
바꾸는 상태     : <before> → <after>
포기 시 잃는 것 : <소비자 ID> + <발화 주차>
서사 위치       : <chapter>.<beat>
장면 계층       : T1 / T2 / T3
닫는 것         : <있으면 명시, 없으면 "없음">
```

### ③ 판정 — 3계층

사용자가 모든 단위를 보면 규모를 감당할 수 없고, Codex 자가 판정만 두면 위
사고가 반복된다.

| 계층 | 무엇을 판정 | 누가 | 비용 |
|---|---|---|---|
| **L1 기계** | 도달성·생산자/독자·패리티·계약·래칫 | 감사 게이트 | 0 |
| **L2 자가** | 증거 양식 전 칸, 깊이 3문 | Codex (기록을 남긴다) | 낮음 |
| **L3 사람** | 문체·감정·재미·인물이 사람인가 | **사용자, 표본만** | 관리 가능 |

### ④ L3의 위임 등급 — 사람이 없을 때 무엇을 닫아도 되는가

L3를 `사용자, 표본만`으로만 두면 사용자를 세울 수 없는 판정이 영구히 열린 채
남는다. 실제로 그렇게 되었다 — 열린 사람 게이트 45건 중 44건이 그 상태였고,
활성 오더 66건 중 44건이 도달 불가능한 L3에 묶여 있었다. 규칙이 없으면 위임은
권한 이양이 아니라 **닫히지 않는 오더가 쌓이는 속도**만 올린다.

L3에는 등급이 있다. 게이트를 만들 때 등급을 함께 정한다.

| 등급 | 무엇 | 누가 닫는가 |
|---|---|---|
| **D1 자율** | 기계로 재는 것 — 정합·커버리지·회귀·바이트 대조·크래시 | 에이전트가 증거를 남기고 닫는다 |
| **D2 위임** | 사람을 세울 수 없는 판정 — 원어민 검수, 외부 다인 독해 | 에이전트가 닫되 **사람이 보지 않았다는 사실을 원장에 남긴다** |
| **D3 사람 전용** | 정상 속도 완주의 재미, 연속 청취, 물리 기기 | 사용자만. 위임하지 않는다 |

- **D2에는 작성자 분리가 강제다.** 원고·번역을 쓴 에이전트가 자기 것을 판정하지
  않는다. 분리할 수 없으면 D2로 닫지 않고 열어 둔다. 이 분리가 없으면 D2는
  검수가 아니라 자화자찬이다.
- **D3에 자동 검사 결과를 합산하지 않는다.** 초록불은 계약을 지켰다는 뜻이지
  재미있다는 뜻이 아니다. D3를 위임하면 그 순간 초록불이 판정이 된다.
- **출시하지 않는 후보의 게이트는 출시를 막지 않는다.** 내부 후보 전용 게이트는
  그렇게 표시하고 출시 판정 목록에서 뺀다. 지우지는 않는다 — 그 후보를 다시
  꺼내면 그대로 유효하다.
- 등급은 낮추는 방향으로만 사용자 지시가 필요하다. D3를 D2로 내리는 것은
  **품질 기준을 내리는 결정**이므로 에이전트가 스스로 하지 않는다.

## 4. 표본 검수

**배치 20단위마다 사용자가 무작위 3개를 본다. 하나라도 불합격이면 배치 전량
반려한다.**

- 어느 것이 뽑힐지 모르므로 전부 잘 만들어야 한다. 15%만 보아도 품질은
  100%에 걸린다.
- 반려가 배치 단위라 `몇 개는 대충`이 성립하지 않는다.
- **표본은 반드시 사용자가 고른다.** Codex가 고르면 잘 만든 것만 올라온다.
- 반려 시 지적받은 단위만이 아니라 배치 전량을 재작업한다.

첫 배치와 정본 성격의 배치는 표본이 아니라 전수로 본다.

**[첫 실행 재조정]** `20단위마다 3개`는 추정이다. 전량 반려와 사용자가 표본을
고른다는 원칙은 유지하고, 표본 수는 첫 배치들의 실제 불합격률로 고친다.
불합격이 잦으면 표본을 늘리고, 계속 통과하면 줄인다.

## 5. 밤샘 실행과의 관계

작게 자르는 것과 대량 실행은 모순이 아니다. `많은 분량을 한 번에`가 아니라
`작은 것을 많이`다.

```
밤   Codex가 단위를 순차 실행. 각각 L1 통과 + L2 증거 기록.
     L1 실패는 스스로 고쳐서 다시 돌린다. 사람을 깨우지 않는다.

아침 사용자가 표본을 지목해 본다.
     통과 → 배치 확정, 다음 배치.
     불합격 → 배치 전량 반려 + 왜 틀렸는지 한 줄. 전량 재작업.
```

## 6. 오더 크기

`ORDER-57` 같은 다단계 대형 오더를 다시 만들지 않는다.

- 오더 하나는 **단위 15~25개, 배치 1~2회** 규모로 끝난다.
- **범위 확장으로 같은 오더에 계속 붙이지 않는다.** 새 발견은 새 오더로
  분리한다. `ORDER-57`이 커진 원인이 정확히 이것이다.
- 오더가 배치 두 회를 넘어가면 쪼갤 신호다.

## 7. 자동 통과는 완료가 아니다

자동 게이트는 **도달 가능성과 계약 충족의 증거이지 재미·깊이·문체의 증거가
아니다.** 완료 보고에 이 문장을 고정으로 남기고, `AUTO PASS`를 사람 GO로
바꾸어 선언하지 않는다.
