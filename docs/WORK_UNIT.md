# WORK_UNIT.md — 작업 단위와 판정 정본

> 이 문서가 **작업을 얼마나 작게 자르고, 무엇을 증거로 삼고, 누가 판정하는지**를
> 소유한다. 큐 운영 절차는 [`CODEX_QUEUE.md`](CODEX_QUEUE.md)가, 장면 계층은
> [`SCENE_TIER.md`](SCENE_TIER.md)가 계속 소유한다.

## 왜 이 규격이 생겼는가

`ORDER-57`은 870줄·범위 확장 20회·6단계로 커졌고 각 단계가 전부 `AUTO PASS`를
받았다. 그런데 아래가 그 스무 번의 통과를 그대로 지나갔다.

- 당시 월별 도달 가능 authored 슬롯 `2/3/3/4/1/1` — 개수 게이트를
  통과시키려다 얕은 사건을 늘릴 위험이 있었고, 현재는 관측값으로만 남긴다
- 생계·성장·회복 축 authored `0/15`
- 체인 시작 사건의 **95%가 1링크**
- 선택 결과문 **중앙값 69자**
- 실제 플레이 타임 10~20분 대 선언 목표 95분

각 단계는 자기 게이트를 통과했는데 **아무도 전체 모양을 보지 않았다.** 오더가
너무 커서 볼 수가 없었다. 단위를 작게 자르는 것은 취향이 아니라 이 사고의
재발 방지다. 분량을 한 번에 처리하면 디테일이 떨어진다.

## 1. 단위

한 단위는 **하나의 판정 가능한 것**이다. 대략 원고 300~800자 또는 파일 1~3개.
이보다 크면 디테일이 떨어지고, 작으면 관리 비용이 산출보다 커진다.

**[첫 실행 재조정]** `300~800자`와 `파일 1~3개`는 실제 배치를 한 번도 돌리지
않고 정한 추정이다. 판정 가능한 단위라는 원칙은 유지하되 숫자는 첫 배치의
반려율로 고친다.

| 작업 종류 | 1단위 |
|---|---|
| 인물 성경 | 인물 1명 (전 칸) |
| 장면 심화 | 장면 1개 (계층 계약 충족까지) |
| 휴면 콜백 부활 | 콜백 1건 (생산자 배선 + 재집필) |
| 챕터 마감 | 4단계 중 1단계 |
| 감사 신설 | 검사 1종 |
| 자산 제작 | 자산 1점 + 계약 배선 |

## 2. 배치

**한 배치는 15~25단위**다. 배치 안의 단위는 **서로 의존하지 않게** 짠다.
하나가 반려돼도 나머지가 무의미해지지 않아야 한다. 의존이 불가피하면 배치를
나눈다.

**[첫 실행 재조정]** `15~25`는 추정이다. 의존 없음이라는 원칙은 유지한다.

## 3. 단위마다 세 관문

### ① 착수 전 — 깊이 3문

답하지 못하면 착수 금지다.

1. **이걸 지우면 다른 무엇이 깨지는가?** — 아무것도 안 깨지면 장식이다.
2. **고른 플레이어와 안 고른 플레이어의 상태가 24주 뒤에 다른가?** — 같으면
   선택이 아니다.
3. **같은 자리에서 무엇과 경쟁하는가?** — 경쟁이 없으면 배분이지 결정이 아니다.

이 셋은 위 실측 결함 전부를 사전에 잡았을 질문이다. 생계 카드는 1번에서,
20주 유혹 1회는 3번에서 걸렸을 것이다.

### ② 완료 시 — 증거 양식

**산문 금지.** 측정값 또는 `file:line`만 쓴다. 한 칸이라도 비면 완료 선언
금지다. `구현했다`는 증거가 아니다.

```
도달 경로      : <실행한 시뮬/검사 출력 원문>
생산자 ↔ 독자   : <file:line> ↔ <file:line>
바꾸는 상태     : <before> → <after>
포기 시 잃는 것 : <소비자 ID> + <발화 주차>
서사 위치       : <chapter>.<beat>
장면 계층       : T1 / T2 / T3
닫는 것         : <있으면 명시, 없으면 "없음">
```

### ③ 판정 — 권한과 증거를 분리

2026-09-09 사용자는 게임 개발·품질 검수·내부 제품의 최종 판단을 Codex에
위임했다. 이 범위에서 사용자 표본 선택이나 재서명을 다음 작업의 필수 조건으로
두지 않는다. Codex는 검수·수리·범위 판단과 후속 실행까지 책임진다. 이 위임이
외부 출시, 스토어 변경, 금전 지출, 법률 인증 권한을 자동으로 주지는 않는다.

저자의 자가 판정만으로는 위 사고가 반복된다. 작성자와 다른 에이전트가 실제
원문·산출물·검수 증거를 직접 읽고 최종 품질을 판단한다.

| 계층 | 무엇을 판정 | 누가 | 비용 |
|---|---|---|---|
| **L1 기계** | 도달성·생산자/독자·패리티·계약·래칫 | 감사 게이트 | 0 |
| **L2 자가** | 증거 양식 전 칸, 깊이 3문 | Codex (기록을 남긴다) | 낮음 |
| **에이전트 최종** | 실제 산출물의 품질, 결함·수리, 적용 범위와 남은 한계 | **저자와 다른 검수 에이전트** | 범위에 맞게 |
| **인간 관찰 증거** | 실제 원어민 독해·인간 플레이·물리 조작감 | 실제 관찰자만 기록 | 관찰한 만큼 |

새 권한과 판정은 [`agent_review_decisions.json`](agent_review_decisions.json)에
기록한다. 검수 보고에는 독립 검수자, 모집단·실제 읽은 범위, 방법, 결함과 수리,
미관찰 한계, GO/HOLD/REWORK의 근거가 있어야 한다. 보고와 증거 파일의 경로·SHA,
검수한 source 또는 package의 commit/tree/manifest, scope를 결속한다. 현재 후보를
판정 기록에서 역으로 추정하지 않는다. 같은 후보·범위의 마지막 판정이 유효하며,
뒤의 HOLD/REWORK를 건너뛰어 과거 GO를 가져오지 않는다.
`work_unit` 판정에는 `unit_id`도 필수다. 검수자가 관측한 현재 작업 ID와 같을 때만
적용하며 다른 작업의 GO를 가져오지 않는다. `internal_product`에는 이 필드를 넣지 않는다.

source 후보는 판정 원장 값이 아니라 실제 Git 이력에서 관측한다. 판정 원장,
`docs/agent_reviews/`의 단일 JSON/Markdown 보고, 큐·WORK_LOG·STATUS 및 명시된
오더 보고서만 바뀐 clean metadata wrapper는 마지막 제품 commit에 결속한다.
고정 허용 경로는 `tools/human_gates.py`의 `AGENT_METADATA_PATHS`와
`AGENT_METADATA_REPORT_RE`가 검사한다. wrapper 전체 diff를 다시 확인하며,
원문·코드·정본·밸런스·인간 원장·출시 manifest는 예외가 아니다. 이 중 하나라도
바뀌면 새 후보이고 과거 GO는 미적용이다. 미커밋 변경이나 신원 확인 실패는 HOLD다.
단, resolver의 생성물인 `docs/STATUS.md` 하나만 미커밋 상태인 경우에는 source
후보를 유지한다. index·작업 트리·untracked 경로를 모두 NUL 구분으로 검사하며,
다른 metadata·코드·원문·미추적 파일이 하나라도 섞이면 이 예외를 적용하지 않는다.

원장의 구조 통과는 품질 GO가 아니다. 독립 검수가 없거나 결함이 남으면 HOLD 또는
REWORK다. 해당 후보·범위의 판정 기록이 없으면 HOLD이며, 위임 자체로 GO가 되지 않는다.
source와 package 판정도 서로 대신하지 않는다. package manifest는 실제 증거 파일의
SHA와 같아야 한다. 이 원장은 인간 증거를 발급하지 않으므로 `unobserved`에는
`native_reader`, `human_playtest`, `physical_controller_feel`을 계속 남긴다.

[`human_gates.json`](human_gates.json)의 과거 state/evidence/delegated_reviews와
후보 신원은 별도다. 기존 L3 OPEN·GO·REJECT의 의미와 실제 인간 증거를 보존한다.
에이전트 검수로 원어민·인간 플레이·물리 패드 감각을 관찰했다고 쓰지 않는다.
인간 증거 OPEN만으로 사용자 응답을 기다리지 않고, 남은 에이전트 검수·수리 또는
제한된 주장과 범위를 정해 계속한다.

## 4. 표본 검수

**배치 20단위마다 독립 검수 에이전트가 무작위 3개를 본다. 하나라도 불합격이면 배치 전량
반려한다.**

- 어느 것이 뽑힐지 모르므로 전부 잘 만들어야 한다. 15%만 보아도 품질은
  100%에 걸린다.
- 반려가 배치 단위라 `몇 개는 대충`이 성립하지 않는다.
- **작성자가 표본을 고르지 않는다.** 독립 검수자가 모집단·seed·추출 방식을
  먼저 봉인해 잘 만든 것만 선택하는 편향을 막는다.
- 반려 시 지적받은 단위만이 아니라 원래 배치 전량을 재작업하고 같은 배치를
  다시 검수한다. 실패 증거를 지우거나 모집단을 줄여 통과시키지 않는다.

첫 배치와 정본 성격의 배치는 표본이 아니라 전수로 본다.

**[첫 실행 재조정]** `20단위마다 3개`는 추정이다. 전량 반려와 독립 표본 추출
원칙은 유지하고, 표본 수는 첫 배치들의 실제 불합격률로 고친다.
불합격이 잦으면 표본을 늘리고, 계속 통과하면 줄인다.

## 5. 밤샘 실행과의 관계

작게 자르는 것과 대량 실행은 모순이 아니다. `많은 분량을 한 번에`가 아니라
`작은 것을 많이`다.

```
밤   Codex가 단위를 순차 실행. 각각 L1 통과 + L2 증거 기록.
     L1 실패는 스스로 고쳐서 다시 돌린다. 사람을 깨우지 않는다.

후속 독립 에이전트가 봉인한 전수/표본을 검수한다. 사용자 재판정을 기다리지 않는다.
     해당 후보·범위 GO → 배치 확정, 다음 배치.
     HOLD/REWORK → 미완료·결함 근거를 남기고 원래 배치 재검수까지 계속한다.
```

## 6. 오더 크기

`ORDER-57` 같은 다단계 대형 오더를 다시 만들지 않는다.

- 오더 하나는 **단위 15~25개, 배치 1~2회** 규모로 끝난다.
- **범위 확장으로 같은 오더에 계속 붙이지 않는다.** 새 발견은 새 오더로
  분리한다. `ORDER-57`이 커진 원인이 정확히 이것이다.
- 오더가 배치 두 회를 넘어가면 쪼갤 신호다.

## 7. 자동 통과는 완료가 아니다

자동 게이트는 **도달 가능성과 계약 충족의 증거이지 재미·깊이·문체의 증거가
아니다.** 완료 보고에 이 문장을 고정으로 남기고, `AUTO PASS`를 에이전트 최종 GO나
사람 GO로 바꾸어 선언하지 않는다. 새 최종 판정과 실제 인간 관찰은 서로 별도다.
