#### [x] ORDER-68 [P0·운영 정합] 데모 출시까지 한 줄로 실행되게 만든다

**사용자 지시 (2026-08-03):** 누적된 분석과 Claude 작업을 정리하고, 모순을
해소한 뒤 순서대로 계속 진행한다.

이 오더는 게임 내용을 바꾸지 않는다. 현재 서로 다른 다음 순서, 큐/사양 상태
불일치, 3~7배치짜리 대형 오더, 빌드 식별자가 없는 사람 게이트를 정리해 이후
작업이 한 항목씩 판정 가능하게 만드는 운영 수리다.

## 착수 전 깊이 3문

1. **지우면 무엇이 깨지는가?** `CLAUDE.md`·`HANDOFF.md`·큐가 서로 다른 다음
   작업을 가리키고, 이미 끝난 배치가 미착수로 보이며, 구 RC가 최신 후보처럼
   남는다.
2. **24주 뒤 상태가 다른가?** 게임 수치는 변하지 않는다. 대신 어떤 후보를
   누가 어떤 리비전에서 판정했는지가 남아 출시 판단이 재현 가능해진다.
3. **무엇과 경쟁하는가?** 모든 기능 작업과 경쟁한다. 그래서 문서 정합과 자동
   검증까지만 수행하고 곧바로 첫 기술 블로커로 넘어간다.

## 배치 A — 실행 정본 수렴

- `CODEX_QUEUE.md`만 우선순위·상태의 정본으로 두고 `CLAUDE.md`와
  `HANDOFF.md`는 현재 항목과 그 링크만 적는다.
- 큐 행과 활성 사양 머리말의 상태를 일치시킨다.
- 2배치를 넘는 사양은 실행 항목이 아닌 부모 계획으로 분류하고, 데모 출시까지
  필요한 다음 조각만 1~2배치짜리 자식 오더로 만든다.
- 사용자 승인으로 확정된 `PROPOSALS.md` P-1~P-3을 결정 기록과 자식 오더로
  옮긴다.

## 배치 B — 사람 게이트와 재발 방지

- 데모 사람 게이트마다 범위, 빌드 리비전, 표본/환경, 합격 기준을 기록한다.
- V2 이전 외부 RC는 현 후보 판정 근거로 재사용하지 못하게 명시한다.
- 큐 행과 활성 사양 상태 불일치를 자동 검사에 연결한다.
- `STATUS.md`를 생성기로 갱신하고 전체 문서 감사를 통과시킨다.
