## 항목과 순서

### B. 표적 감사 — 완료

`tools/audit_scope.json`이 변경 파일 글롭 → 검사 매핑을 소유하고
`tools/audit_select.py`가 필요한 검사만 고른다.

- 매칭 규칙이 없는 변경은 **전체 감사를 요구한다**(안전 기본값). 조용히
  건너뛰지 않는다.
- `--verify`가 `audit.sh`의 검사가 전부 등록됐는지 확인한다. 새 검사를
  `audit.sh`에 추가하고 여기 등록하지 않으면 실패로 보고된다.
- **표적 감사는 전체 감사를 대체하지 않는다.** 배치 마감과 CI는 계속
  `audit.sh`를 돈다.

측정: 문서 변경 1건에 0.9초(검사 2개), 사건 JSON 1건에 검사 28개.

### C. 스킬 — 프로토콜을 호출 가능하게

**[~] 2026-07-31 부분 완료 (Claude).** 계획은 `.claude/skills/`를 가정했는데
**실제로 작업하는 것은 Codex이고 `.codex/skills/`가 이미 있었다.** 잘 쓰인
`gangnamdream-dev` 스킬이 부팅·작업·검증·마감을 덮고 있었다. 두 가지를 했다.

- `gangnamdream-dev`의 검증 절에 **`tools/audit_select.py`를 명시**했다. 기존
  문구는 `narrow check를 먼저 돌려라`였을 뿐 도구 이름이 없어, Codex가 매번
  10분짜리 전체 감사를 돌릴 여지가 있었다. 래칫 검사의 기준선 갱신 규칙과
  **기준선을 넓혀 실패를 없애지 않는다**도 함께 넣었다.
- **`gangnamdream-scene` 신규.** 아래 표의 `/scene-new`에 해당한다. 계층·계약·
  자산·연출·대가·화자 지식을 **산문보다 먼저** 확정시킨다.

나머지(`/unit-start`·`/unit-done`·`/batch-review`·`/canon-check`·`/order-new`)는
미착수다. `gangnamdream-dev`가 이미 착수 선언과 마감 절차를 덮으므로 이득이
작고, 스킬을 늘리면 Codex가 어느 것을 부를지 고르는 비용이 생긴다.

원래 계획은 아래와 같다. 스킬은 정본을 복사하지 않고 가리키기만 한다 — 복사본은
낡는다.

| 스킬 | 하는 일 |
|---|---|
| `/unit-start` | 깊이 3문 → 답 없으면 착수 거부 → 착수 선언 커밋 |
| `/unit-done` | 증거 양식 수집 → 표적 감사 실행 → 빈 칸이면 완료 거부 |
| `/batch-review` | 배치 목록 제시 → 사용자가 표본 지목 → 반려 시 전량 표시 |
| `/scene-new` | 계층을 묻고 그 계약대로 골격 생성. 자산 부재면 차단 |
| `/canon-check` | 규범 문장 추출 → 정본 소유자 대조(한영 양쪽 검색) |
| `/order-new` | 오더 템플릿. 단위 25개 초과 시 분할 경고 |

`/scene-new`가 특히 중요하다. 지금은 다 쓴 뒤 감사가 계약 위반을 잡는데,
스킬은 **쓰기 전에 계약이 골격을 강제**한다. 사후 검출을 사전 예방으로
옮기는 것이 1링크 95% 재발을 막는 유일한 방법이다.

### F. 정합 — 지식 원장과 단계별 화계

대화량을 늘리면 반드시 깨지는 지점이다. 현재 `story_rules.json`은 사건
하위 키가 `logic`·`presentation` 둘뿐이라 **누가 말하는지도, 그 인물이 무엇을
아는지도 표현할 자리가 없다.** `fact_types`도 셋뿐이고 다은 관계 단계는
typed fact가 아니다.

**원칙: 인물은 알 경로가 증명되지 않은 것을 언급할 수 없다.** 인물이 아는
것은 넷뿐이다 — 직접 참여한 사건, 명시적으로 전달받은 것, 세계 공개 사실,
자기 자신. 화이트리스트가 아니라 블랙리스트로 가면 반드시 뚫린다.

사건마다 `speech.speakers`와 `speech.references`를 선언하고, 감사는 각 참조에
대해 **도달 가능한 모든 경로에서** 그 화자가 그 시점에 알 수 있는지 묻는다.
한 경로라도 모른 채 도달할 수 있으면 실패다. 존재가 아니라 전칭이어야 한다.

함께 필요한 것:

- 다은 관계 단계를 `fact_types`로 승격. 지연만 있는 것은 누락이다.
- `speech_register_audit.py`를 하드코딩 사건 목록에서 **규칙 기반**으로
  전환한다. 지금 구조로는 새로 쓰는 장면이 자동 보호되지 않는다.
- 단계별 호칭·화계·금지 표현 계약.
- 시점 계약 — 아직 일어나지 않은 사건을 과거로, 지난 사건을 미래로 언급하지
  않는다.

**적용 범위: 신규 장면부터 필수, 기존 1,581건은 래칫으로 악화만 막는다.**
전부 채우고 시작하면 영원히 시작하지 못한다.

### A. `MainGame.gd` 분해

19,984줄·688함수. 게임플레이를 건드리는 모든 에이전트가 여는 파일이라 병렬
작업의 물리적 한계다. 함수 접두사가 이미 모듈 경계다.

| 접두사 | 함수 | 추출 후보 |
|---|---:|---|
| `_ap*` | 42 | `systems/ApActions.gd` |
| `_ending*` | 37 | `systems/EndingFlow.gd` |
| `_core*` | 34 | `systems/CoreLoopBridge.gd` |
| `_build*`·`_render*`·`_open*` | 83 | `ui/DashboardBuilder.gd`, `ui/ModalKit.gd` |
| `_demo*` | 22 | `systems/DemoFlow.gd` |
| `_weekly*` | 17 | `systems/WeeklyEconomy.gd` |
| `_job*`·`_people*` | 23 | `systems/JobFlow.gd`, `systems/PeopleFlow.gd` |

방식이 결과보다 중요하다.

- **1추출 = 1단위 = 1커밋.**
- **행동 불변이 유일한 합격 기준.** 추출 전후로 전체 감사와 240주 대표 경로
  출력이 동일해야 한다. 리팩터링에 기능 변경을 섞지 않는다.
- 추출 모듈이 자체 상태를 갖지 않는다. 상태는 계속 `GameState` 경유
  (`MainGame 재생성` 함정 재발 방지).
- 의존이 적은 끝단부터. `_ending*`·`_job*`이 첫 후보이고 `_build*`·`_render*`가
  마지막이다.

**A가 마지막인 이유**는 이 저장소에서 가장 위험한 작업이고, 표적 감사·스킬·
린트가 갖춰진 뒤에 해야 안전하기 때문이다.
