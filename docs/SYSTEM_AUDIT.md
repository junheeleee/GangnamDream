> 유저 지적: *"이게임의 모든 AP행동, 아이템, 관계, 뉴스, 투자, 알바, 취업, 스토리 선택지, 카지노, 경마, 홀덤 등 모든 시스템이 난개발되면서 서로 유기적으로 작동하지 않고 죽은 코드가 너무 많다."*

## 0. 한 줄 결론

**게임은 작동한다. 하지만 시스템들이 `GameState`의 스탯 풀이라는 하나의 가는 공유 버스로만 간접 연결되고, 서로를 직접 보지 않는다.** 그 버스에 흐르는 신호는 사실상 `mental`과 `money` 둘뿐이다. 그 결과 ①직접 인과(아이템→이벤트 해금, cast→투자, 뉴스→취업, 미니게임→서사)가 거의 없고 ②각 시스템이 독립적으로 팽창하며 죽은 코드·중복·모순을 쌓았다.

핵심 지표 3개로 요약되는 난개발의 정량적 증거:
- **플래그 977개 중 23%(225개)가 write-only** — 플레이어 선택의 1/4이 게임 상태에 흔적을 안 남긴다.
- **선택지의 79%가 `mental`만 건드린다** — 8~9개 스탯·route·cast·tendency 분기 인프라를 깔아놓고 콘텐츠는 한 축으로 수렴.
- **이벤트의 10.5%(122개)가 inert** — 다중 선택지인데 효과·플래그·분기 전부 동일한 "가짜 분기".

## 1. 통합 패턴 — "스탯 풀 버스"

```
        ┌─────────────────── GameState (스탯/플래그/market_context) ───────────────────┐
        │   ↑쓰기              ↑쓰기            ↑쓰기          ↑쓰기         ↑쓰기        │
   [AP행동]   [아이템]   [이벤트선택지]   [투자]   [취업/알바]   [미니게임]   [관계/cast]
        │                                                                                │
        └── 시스템끼리는 서로를 거의 호출하지 않음. 전부 이 버스를 경유한 간접 연결만 ──┘
```

**잘 연결된 배선 (살아있는 축):**
- `mental` — 투자 수수료, 관계 소멸 속도, 이벤트 가중치, 게임오버까지 전방위.
- `market_context`(news가 씀) — InvestmentSystem(가격) + EventManager(조건·가중치) 둘 다 읽음.
- `get_credit_score()` — 취업+자산+평판을 묶어 대출→투자자금으로 환류시키는 유일한 직업↔투자 다리.
- 성향(gambling/addiction) — 미니게임 플레이 → tendency → 중독 아크 → 회복 엔딩 (이 한 축은 실제로 유기적).

**그 외 모든 시스템 간 직접 인과는 단절.**
