# 강남드림 출시용 비주얼/오디오 제작 파이프라인

Updated: 2026-07-19

## 목적

이 문서는 강남드림의 외형 작업을 "AI로 이미지 몇 장 생성" 단계에서 "상용 출시 가능한 아트/오디오 제작" 단계로 올리기 위한 기준이다. `assets/CHARACTER_VISUAL_BIBLE.md`, `docs/UI_ART_DIRECTION.md`, `docs/ASSET_QA.md`, `docs/AUDIO_QA.md`, `assets/VISUAL_AUDIO_UPGRADE_BRIEF.md`보다 상위의 제작 게이트로 사용한다.

핵심 전제:

- AI 이미지/오디오 사용 자체가 문제가 아니다.
- 문제는 raw AI 결과물이 그대로 들어가서 정합성, 저작권/상표권, 스타일, UI 통합, 사운드 밀도 검수를 통과하지 못하는 것이다.
- 출시 에셋은 "생성 결과물"이 아니라 "기획, 생성, 보정, 통합, QA를 거친 게임 리소스"여야 한다.

## 역할 분담

- Claude: 스토리, 아크, 이벤트, 개연성, 밸런스, 텍스트 품질.
- Codex: 비주얼, 오디오, UI/UX, 미니게임 연출, Godot 통합, 스크린샷 QA.
- 외부 툴/작업자: 고품질 이미지 생성, 페인트오버, 리터칭, 업스케일, SFX/BGM 제작, 믹싱/마스터링.

Codex는 외부 툴을 직접 호출하지 못하는 상황에서도 이 문서를 기준으로 필요한 산출물, 파일명, 규격, QA 기준, 교체 우선순위를 관리한다.

## 외부 툴 사용 원칙

### 구매/외주 우선순위

엔진 이전이나 범용 에셋 팩 구매를 품질 개선의 지름길로 보지 않는다. 강남드림의 병목은 렌더러가 아니라 얼굴·장소·소품 정합성과 오디오 정체성이다. 예산은 다음 순서로 쓴다.

1. **핵심 CG·키아트 최종 페인트오버**: T0/T1, 주요 엔딩, Steam 캡슐처럼 가장 많이 공유되는 12~20장을 사람 아티스트가 얼굴·손·원근·차량·가짜 글자를 정리한다.
2. **메인 테마와 moral 3변주**: 같은 선율이 Gray/Black/White에서 악기·공간·왜곡으로 달라지는 한 묶음을 작곡·믹싱한다.
3. **상업 라이선스 SFX·앰비언스**: UI, 서울 실내외, 카지노 기계, 카드·칩·동전처럼 범용성이 높고 직접 제작해도 고유성 이득이 작은 소리를 구매한다.
4. **Steam 캡슐·트레일러 마감**: 게임 첫인상을 전문 그래픽 디자인과 사운드 편집으로 승격한다.
5. **영어 네이티브 에디팅·플레이 QA**: 외국 출시에서 아트만큼 직접 체감되는 품질 비용으로 본다.

구매하지 않는 것:

- 강남드림의 moral 반응형 표면을 대체할 범용 판타지·사이버·모바일 UI 팩.
- 주연 얼굴과 의상을 고정할 수 없는 범용 캐릭터 팩.
- 현재 Godot 코드·감사·데이터 구조를 버리게 만드는 엔진 전용 프레임워크.
- 전체 게임의 문법과 맞지 않는 화려한 VFX·Live2D·3D 환경 팩.

예산 배분의 기본값은 CG/키아트 35%, 음악·사운드 25%, 캡슐·트레일러 20%, UI 마감 10%, EN 최종 QA 10%다. 실제 계약 전에는 상업 사용 범위, Steam 배포, 수정권, AI 사용·학습 데이터 고지, 원본 파일 제공 여부를 문서로 남긴다.

### 이미지

허용 파이프라인:

1. 콘티/캐릭터 시트/장소 시트 작성.
2. 상업 사용 가능한 생성 툴 또는 커미션으로 초안 제작.
3. Photoshop, Clip Studio, Affinity, Firefly류 보정 툴 등으로 손/얼굴/소품/텍스트/로고/구도 수정.
4. 필요 시 업스케일과 노이즈 정리.
5. 게임 팔레트로 색보정.
6. Godot 실제 화면에 넣고 스크린샷 QA.

금지:

- 저작권 있는 사진을 거의 그대로 변환한 이미지.
- 워터마크, 신문사 로고, 실제 브랜드 로고, 읽히는 간판/상표.
- "강원랜드", 실제 카지노/은행/회사명을 직접 읽을 수 있는 이미지.
- 캐릭터 포트레이트에 반복 배경이 박힌 파일.
- 고시원, 가족집, 지연 차량, 회사 면접실처럼 정본이 중요한 장소의 구조를 임의로 바꾸는 이미지.

### 오디오

허용 파이프라인:

1. 장면별 사운드 스펙 작성.
2. 상업 사용 가능한 SFX/BGM 생성, 구매, 녹음, 커미션.
3. Reaper, Audition, Logic, Ableton류 DAW에서 볼륨, EQ, 루프, tail, 노멀라이즈 정리.
4. Godot `AudioManager`/`BGMPlayer`에 키 기반으로 연결.
5. 실제 플레이에서 반복 피로도, 전환 끊김, 음량 균형 QA.

금지:

- 라이선스 문서 없는 무료 음원.
- 유명 음악/효과음과 혼동될 정도로 닮은 사운드.
- 한 UI 클릭음으로 모든 피드백을 때우는 방식.
- 이벤트마다 BGM이 처음부터 재시작되어 조잡하게 들리는 전환.

### Gate 1. 산출물 스펙 고정

생성 전에 파일별로 아래를 고정한다.

- 파일 경로와 해상도.
- 배경/포트레이트/CG/UI/오디오 분류.
- 화면 내 사용 위치와 크롭 방식.
- 실제 1280x800 선택지·결과판·대사창 아래에서 핵심 얼굴/손/행동이 남는 안전 영역.
- CG 인물별 장면 표정과 시선 목표. 신원 레퍼런스의 기본 표정은 자동 상속하지 않는다.
- 금지 요소.
- 합격 기준.
- 대체 fallback.

#### 해상도 마스터 계약

`1280x800`은 강남드림의 논리 UI 캔버스이자 Steam Deck 기준 해상도다. 출시 원화의 최종 제작 해상도를 뜻하지 않는다. 전체화면 배경과 CG는 `KEEP_ASPECT_COVERED`로 표시되므로 16:10 원본이 16:9 화면을 덮을 때 위아래가 잘리는 것까지 포함해 균일 확대율을 계산한다.

| 용도 | 현재 다수 원본 | 1080p native master | P0 4K master | 판정 |
|---|---:|---:|---:|---|
| 전체화면 배경/CG | 1280x800 | 1920x1200 | 3840x2400 | 현재 원본은 1080p 1.5x, 4K 3x 확대 |
| 투명 포트레이트 | 512x768 | 512x768 | 1024x1536 | 현재 원본은 1080p native, 4K 2x 확대 |
| UI 선·프레임·아이콘 | SVG/코드 우선 | 벡터/코드 | 벡터/코드 | 래스터 확대본으로 교체하지 않음 |

- P0는 실제 데모 노출, Steam 상점 캡처, A/A+/S/S+ 엔딩 원화다. 이들은 최종 얼굴·손·글자·구도를 고정한 뒤 `3840x2400` 또는 `1024x1536`에서 다시 제작/페인트오버한다.
- P1 반복 배경은 최종 4K 마스터가 준비되기 전 `2560x1600` 이상을 중간 납품 기준으로 사용할 수 있다. 이 경우 4K에서 최대 1.5x 확대되는 사실을 출시 QA에 남긴다.
- 원본 제작 파일은 레이어와 생성/수정 이력을 보존하고, 게임에는 Godot import 압축을 거친 최종 PNG만 연결한다. 단순히 파일 크기만 키운 보간본을 새 원본이라고 부르지 않는다.
- 현황과 우선순위는 `python3 tools/art_resolution_audit.py`와 `docs/ART_RESOLUTION_READINESS.md`가 정본이다. 활성 경로 추가·삭제 또는 가로/세로 해상도 하락은 기준선 검토 전 전체 audit를 실패시킨다.

외부 업스케일 사용 판정:

- 사람·손·거울·차량 로고·읽히는 글자가 있는 P0 CG는 원화 재제작 또는 사람 페인트오버가 우선이다. 블라인드 초해상도 결과만으로 A/S 판정을 내리지 않는다.
- 익명 인물만 있거나 인물이 없는 깨끗한 장소 배경은 동일 모델·버전·설정으로 오프라인 초해상도 A/B를 만들 수 있다. 100% 크롭에서 문/창/가구 원근, 간판, 반복 무늬를 승인한 결과만 교체한다.
- 투명 포트레이트는 알파 인지 2x 공정을 사용하고 머리카락 경계, 눈 정체성, 손, 의상 실루엣을 기존 인물 계약과 대조한다.
- Lanczos/bicubic 보간은 레이아웃 미리보기용일 뿐 출시 마스터 제작 공정이 아니다.

#### 결정론적 초해상도 실행 계약

- 승인된 첫 파일과 정확한 설정·해시·100% 크롭은 `tools/art_master_manifest.json`과 `docs/ART_MASTER_PRODUCTION.md`가 정본이다.
- 공식 Real-ESRGAN NCNN Vulkan v0.2.5.0의 로컬 바이너리와 `realesrgan-x4plus` 모델은 `tools/art_master_pipeline.py`가 배포·모델 SHA-256을 먼저 대조한다. 바이너리와 모델 자체는 저장소에 넣지 않는다.
- 후보는 Godot 프로젝트 밖 시스템 임시 폴더에만 생성한다. 프로젝트의 `build/`도 Godot 파일 스캐너 대상이 될 수 있으므로 A/B 시트를 두지 않는다.
- 1280x800 소스는 타일 크기 1280의 단일 전체 프레임으로 처리한다. 256px와 auto 타일은 실제 복도 파일에서 사각 명암 이음새가 발생했으므로 승격 금지다.
- `--promote`는 매니페스트에 완료된 사람 `PASS`, 출력 SHA-256, 세 곳 이상의 100% 크롭이 있고 명시적 `--human-review-pass`가 있을 때만 허용한다.
- `python3 tools/art_master_audit.py`는 라이선스·공식 URL·도구/모델/입출력 해시·전체 프레임 타일·크롭 판정·런타임 파일을 검사하며 전체 `audit.sh`에 포함된다.

예:

```text
asset_id: jeongseon_casino_entrance
path: assets/backgrounds/jeongseon_casino_entrance.png
type: reusable background
resolution: 1280x800
usage: casino hub, first entrance event
must_have: player-eye-level entrance, generic "CASINO" sign, mountain resort mood
must_not: Kangwon Land logo, news watermark, aerial view, readable real brand
qa: ScreenshotQA 08_jeongseon_casino
grade_target: A
```

### Gate 2. 제작/보정

이미지는 raw 생성물을 그대로 넣지 않는다.

필수 보정:

- 손, 눈, 귀, 목, 옷깃, 소품 형태.
- 얼굴 동일성.
- 배경 원근/구조.
- 이상한 글자/가짜 간판 제거.
- 상표/로고 제거.
- 색온도와 대비 통일.
- 알파 포트레이트 가장자리 정리.

핵심 CG 색 규칙:

- 일반 배경과 HUD는 절제된 `Gangnam Ink` 저채도를 유지한다.
- 로맨스·엔딩·폭로 CG는 Gray에서도 사건의 색을 읽을 수 있어야 한다.
- Black은 단순 검정 오버레이가 아니라 색·공기·수평 안정감을 회수한다.
- White는 UI를 하얗게 칠하지 않고 장면의 명료도·온기·호흡을 회복한다.
- 일본 VN의 얼굴 판독성·시선선·hold·reveal 문법은 사용하되, 인물·장소·계급 신호는 한국 정본을 유지한다.

오디오는 raw 생성물을 그대로 넣지 않는다.

필수 보정:

- 루프 클릭 제거.
- 시작/끝 tail 정리.
- UI/SFX 피크 과다 방지.
- BGM과 SFX가 서로 묻히지 않게 음량 정리.
- 반복 플레이 10분 기준 피로도 확인.

### Gate 3. Godot 통합

이미지:

- `ImageRegistry.gd` 또는 직접 참조 경로 등록.
- 포트레이트는 투명 PNG 유지.
- 배경은 사람/주연이 박히지 않은 재사용 구조 유지.
- CG는 별도 포트레이트 프레임을 띄우지 않음.
- CG가 사건 중간에 등장하면 `cg_reveal_paragraph`로 텍스트 시간과 화면 시간을 맞춤.
- ScreenshotQA 또는 VisualCropQA에 대표 화면 추가.

오디오:

- `AudioManager.play("key")` 키가 실제 파일로 해석돼야 함.
- BGM은 상황 전환 시 crossfade 또는 상태 유지.
- 카지노/투자/엔딩/위기 SFX는 서로 다른 키 사용.
- `tools/AudioAssetCheck.tscn` 통과.

### Gate 4. 플레이어 관점 QA

합격 질문:

- 1초 안에 어떤 장소인지 읽히는가?
- 외국인이 봐도 주요 인물들이 구분되는가?
- 이 화면이 웹 게시판/목업이 아니라 게임 화면처럼 보이는가?
- 돈을 잃거나 벌 때 소리와 모션이 즉시 반응하는가?
- 같은 장소가 다른 이벤트에서 구조적으로 모순되지 않는가?
- Steam 스크린샷으로 공개해도 부끄럽지 않은가?

## 현재 프로젝트에 대한 판단

지금까지의 repo 내부 개선은 필요했고, 계속 가치가 있다. 하지만 2만원대 Steam 출시와 Metacritic 80+를 노리려면, 핵심 노출 에셋은 raw AI generation이 아니라 production pass를 거쳐야 한다.

따라서 앞으로 Codex의 외형 작업 기준은 다음과 같다.

- 기능 개선과 동시에 상용 제작 파이프라인을 남긴다.
- 새 이미지/오디오는 반드시 정합성 문서와 QA에 연결한다.
- "예쁜 이미지"보다 "게임 스토리에 맞는 리소스"를 우선한다.
- 핵심 화면은 ScreenshotQA로 직접 확인한다.
- Claude가 스토리/이벤트를 확장해도 에셋 구조가 무너지지 않게, 반복 인물/장소/CG 레이어 분리를 유지한다.
