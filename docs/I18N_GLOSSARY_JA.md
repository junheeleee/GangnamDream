### 부끄러움의 문법

- 다은은 솔직한 수줍음이다. 문장을 끝까지 말하되 작은 머뭇거림은 `……`과 호흡으로 표현한다.
- 지연은 도도의 균열이다. 감정을 직접 설명하지 않고 시선, 귀 끝, 멈춘 젓가락, 반 박자 늦은 대답으로 보인다.
- 민준의 내면은 `俺`를 반복하지 않는다. 일본어가 자연스러우면 주어를 생략하고, 자기혐오는 과장된 애니 독백보다 짧은 관찰로 남긴다.
- 한국어 존댓말 차이는 일본어의 です・ます／タメ口로 재현하되, 모든 문장을 기계적으로 `です`로 끝내지 않는다.

- 통화는 모든 언어에서 한국 원화다. `円`이나 `¥`로 바꾸지 않는다.

- `배당`은 주식=`配当`, 도박 payout=`払戻倍率／配当`을 문맥에 맞게 구분.

### 문맥 UI ID

ORDER-96 당시의 한국어 원문 키 2,730개는 삭제하거나 이름을 바꾸지 않았고, 같은
한국어가 서로 다른 뜻으로 쓰이는 28키만 30개 안정 문맥 ID·37호출로 분리했다.
ORDER-97의 포맷 템플릿 이동 리비전은 `legacy 2,780키 + context 30 ID`,
`3,310 = legacy 3,273 + context 37`호출이었다. 이후 ORDER-98의 직접 게임 패드
힌트·페이지·진동 설정 copy를 옮긴 당시 snapshot은
`legacy 2,782키 + context 30 ID`, `3,313 = legacy 3,276 + context 37`호출이었다.
active demo_rc의 현재 collector는 `legacy 2,821키 + context 29 ID = 2,850키`,
`3,320 = legacy 3,286 + context 34`호출을 요구한다.
문맥 ID는 `ui_<code>.json`의 다른 행과 같은 최상위 문자열 키이며, 사건 ID나
gameplay key가 아니다. 제품은 현재 잠긴 34곳에서만 문맥 ID를 조회하고 일본어
사전은 도달 29행을 모두 소유한다.

- 일본어 문맥 번역은 각 ID의 실제 KO·EN 인자와 소유 함수에서 판정한다. 같은
  한국어의 legacy 번역을 기계적으로 복사하지 않는다.
- legacy 원문에 붙은 exact 번역 규칙은 문맥 행을 덮어쓰거나 거부하지 않는다.
  예를 들어 legacy `도박장`의 `カジノ`와 장소 목록 제목
  `ui.gambling.venues_title`은 서로 다른 번역 단위다.
- 기존 커뮤니티 언어팩은 한국어 키만으로 계속 작동한다. 신형 팩은 같은 flat
  JSON에 문맥 ID를 추가할 수 있으며, 명시 문맥 행이 있을 때만 그 행이 우선한다.
- 자동 감사는 `legacy 2,821/2,821 + context 29/29 = 2,850/2,850`을 요구한다.
  키 수 통과는 일본어 문맥·버튼 품사·badge 온도의 사람 판정을 대신하지 않는다.

### 값이 들어가는 UI 템플릿

- 숫자·이름·날짜·금액을 먼저 넣어 완성한 문자열을 번역 키로 쓰지 않는다.
  `ui_format`은 안정 한국어 템플릿을 먼저 찾은 뒤 값을 넣는다.
- 일본어 템플릿의 `%s/%d` 변환 종류·개수·순서는 한국어 템플릿과 같고 실제
  줄바꿈 수도 같아야 한다. `%d`와 `%02d`처럼 폭·0 패딩만 다른 것은 허용하지만,
  명시적 `+` 부호와 정밀도는 숫자 의미 계약이므로 한국어와 같아야 한다. 한국어와
  영어 템플릿은 각자 자기 인자 목록을 독립 검증하므로 복수형 등으로 인자 개수가
  달라도 된다.
- 일본어 사전 hit는 대상 언어 인자를 쓰고, miss는 영어 템플릿과 명시 영어
  인자를 함께 쓴다. 현재 locale로 만든 금액이나 문구를 두 인자 목록에 공유해
  영어 부모 안에 일본어가 섞이게 만들지 않는다.
- 착수 raw 원장은 `56 = 이동 48 + 동적 pair reader 4 + branch literal 2 +
  exact-money formatter 2`다. Aruba의 기존 포맷 부모와 GameState의 연말 장면
  선택 따옴표 2건은 raw 56 밖의 별도 provenance 보강이므로 런타임
  `ui_format`은 `48 + 2 = 50`호출이다.
- 정확 1원 단위 표면은 `CommitmentTask::_format_money`와
  `SeoulCycleBoard::_format_money` 두 owner만 가진다. 일본어는 부호·쉼표·정수값을
  보존하고 단위를 `ウォン`으로 쓰며 `円`이나 `¥`로 바꾸지 않는다.
- `ui_ja.json`의 raw JSON 키는 모두 유일해야 한다. 파서가 마지막 값을 남겨
  effective 수가 맞더라도 중복 키가 있으면 감사 실패다.

ORDER-97 L3 사람 판정은 아직 OPEN이다. 같은 후보에서 Batch A 23호출 중 임의의
실제 3표면과 Batch B 24호출 중 임의의 실제 3표면을 각각 보고, 하나라도 영어
fallback·잘못된 값 provenance·문맥 오류가 있으면 그 배치 전량을 반려한다. 현재
해당 후보의 `2,845/2,845` 키 수와 자동 검사는 이 화면 증거를 대신하지 않는다.

## 문장·기호 규칙

- 대화는 일본어 괄호 `「……」`, 장면 안 독백은 `（……）`를 우선한다. 원문의 화자 구분이 무너지지 않게 줄바꿈을 보존한다.
- 말줄임표는 `……`, 강한 단절은 `――`. `...`와 `—`를 일본어 본문에 남기지 않는다.
- `{name}`, `{money}`, `{housing}`, `{p}`, `%s`, `%d`, `\n`, BBCode 태그와 숫자 의미를 절대 바꾸지 않는다.
- `MORAL_TINT`, 도덕 점수, 루트 수치는 일본어 UI에도 직접 노출하지 않는다.
- 선택지는 결과를 미리 설교하지 않는다. 원문의 불편함과 모호함을 번역자가 친절하게 해설하지 않는다.
- 원문 문단 수와 감각 비트는 유지한다. 긴 문장을 줄이는 것은 허용하지만 장면 자체를 요약하지 않는다.

## 고유 정서·마케팅

- 강남은 단순 지명이 아니라 부·계급·도착의 상징이다. 첫 노출만 설명하고 이후에는 `カンナム`이라는 고유명사가 그 무게를 갖게 한다.
- 작품의 질문은 답안으로 번역하지 않는다. `같은 길을 오르면서, 같은 사람이 되지 않을 수 있을까`는 `同じ道を上りながら、同じ人間にならずにいられるのか。`를 정본으로 한다.
- `돈을 따라갈수록 무엇이 남는가`처럼 결말을 미리 해설하는 홍보 카피는 금지한다.
- Moral Tint 변화는 선악 게이지가 아니라 민준의 지각과 인간성 붕괴다. 일본어도 `善悪値`, `カルマ`로 명명하지 않는다.
