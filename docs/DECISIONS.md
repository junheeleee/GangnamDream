# Gangnam Dream Decisions

## 2026-06-11 (감사 체계 확장 — 유지보수성의 구조적 해법)

- **문제 진단**: 게임이 커질수록 버그·서사 모순·유지보수 비용이 증가. 근본 원인은 "진실의 다중화" — 같은 사실(파산 기준, 플래그, stage 이름, 직렬화 대상)이 코드·JSON·문서·시뮬에 중복돼 있고 일치를 강제하는 장치가 없음. AI 세션 기반 개발은 생성 속도가 사람의 검토 속도를 넘어서므로 이 어긋남이 조용히 누적된다.
- **원칙**: 버그를 하나 고칠 때마다 그 버그의 "클래스 전체를 잡는 검사"를 audit에 추가한다 (플래그 교차 검증이 선례 — 도입 시 15건 일괄 검출). 이번 4종도 도입 즉시 9건 검출.
- **화이트리스트는 코드에서 동적 파싱**: effects/conditions 허용 키를 하드코딩하지 않고 apply_effects·_check_conditions의 match 문에서 추출 — 코드가 진실이고 목록은 자동 동기화. 하드코딩 목록은 그 자체가 또 하나의 중복된 진실이 되기 때문.
- **stage 정본 파일**: cast_stages.json은 검사용 선언이지만, 새 stage를 "먼저 선언하고 쓰는" 워크플로를 강제해 서사 상태 공간을 명시적으로 관리하게 한다.
- **밸런스 밴드는 시드 고정**: 결정적이므로 밴드 이탈 = 코드 변경의 파급. 의도된 조정이면 BALANCE.md 기록과 밴드 갱신을 같이 하도록 메시지에 명시.

## 2026-06-11 (파산 기준 순자산화 + 대출 시스템)

- **파산 -3천만이 과했던 이유**: 유저 피드백("3천 빚졌다고 파산은 심해") + 문서/UI/엔딩 텍스트가 전부 -1억 기준으로 쓰여 있었는데 check_game_over 상수만 -3천만이었음. 코드를 설계값(-1억/-2억)으로 정렬.
- **판정을 현금 → 순자산으로**: 대출 도입 시 "빌린 현금"이 통장에 있으면 현금 기준 파산은 영원히 안 옴. 순자산(현금+포트폴리오-대출원금) 기준이면 빌린 돈을 날리는 순간 파산선에 다가감 — 레버리지의 위험이 정직하게 작동.
- **대출 한도 설계**: 1금융 = 월소득×12 (직장 신용) — 기본 연봉이면 한도 전액 손실해도 순자산 -5,700만으로 파산선 위(빚만 남은 채 생존). 4티어 고연봉은 한도 ~1.3억이라 전액 손실 시 파산 가능. "판이 클수록 추락도 깊다"가 자연 스케일링됨. 제2금융은 무직도 가능한 3천만/연 21.6% — 빠르지만 비싼 돈.
- **승리 조건 부풀림 방지**: get_total_asset_value가 대출원금을 차감하므로 대출로 30억 달성·자산 마일스톤·재산 칭호를 찍을 수 없다.
- **신용등급 도입 (유저 지시)**: 고정 한도·금리 대신 신용점수(고용·근속·소득·순자산·평판 − 부채비율·바닥이력) → 1~10등급이 한도·금리를 결정. **변동금리**를 택한 이유: 대출 시점 고정금리는 "빌리고 나면 끝"이라 긴장이 없다. 매달 현재 등급으로 이자를 재계산하면 실직·자산 손실이 보유한 빚의 이자 상승으로 즉시 전이 — 현실의 "빚의 악순환"이 메커니즘으로 작동하고, 등급 관리(근속·자산·상환)가 지속적인 인센티브가 된다. 저장 데이터도 원금만 있으면 돼서 세이브 호환이 단순해지는 부수 이점.

## 2026-06-11 (아크와 자원 게임의 역할 분리)

- **딜레마**: 아크 선택이 엔딩을 직접 가르면 플레이어가 아크 선택지만 최적화하고 자원/스탯 관리가 무의미해진다. 반대로 아크가 엔딩에 영향이 없으면 "내 선택으로 결말이 달라진다"는 체감이 사라진다.
- **결정**: "엔딩의 크기는 숫자가, 표정은 관계가 정한다." (1) 엔딩 티어(승리/파산/번아웃)는 자산·스탯이 단독 결정 — 아크만으로는 30억이 안 모이고 인물 접촉은 AP를 소모하므로 아크 추구 자체가 자원 관리의 일부. (2) 아크 상태는 엔딩 *에필로그*를 변형 — 같은 승리도 따뜻한 승리와 공허한 승리로 갈림. (3) 아크 보상은 런 중 경제 이득으로 환류(월간 패시브, 정보 이벤트) — 아크와 숫자 게임이 경쟁이 아닌 보완 관계. (4) 관계가 엔딩을 *뒤집는* 게이트는 lonely_rich/empty_house 두 개만 유지 — 전부 게이트화하면 아크가 체크리스트가 된다. 페르소나의 팰리스(본 게임)/코프(관계) 구조와 동일한 원리.
- **상철 정보 이벤트 EV**: 신뢰 보상인 만큼 일반 시장 베팅보다 유리하게(성공률 0.62, 실패 시 손실 50%) 설계하되, "확실한 건 없다"는 대사로 손실 가능성을 명시 — 멘토 신뢰가 무위험 치트가 되지 않게 한다.

## 2026-06-10 (플래그 교차 검증 — 반복되는 불일치의 구조적 해결)

- **왜 도입했나**: 아크/선택지를 들여다볼 때마다 수정거리가 계속 나왔다. 원인은 게임의 모든 연결(아크 진행, 패널 표시, 엔딩 게이트, 이벤트 조건)이 문자열 플래그로 돼 있는데 set와 read의 일치를 검증하는 장치가 전무했기 때문. 사람이 조심하는 방식은 이미 실패했으므로(도입 시점 잠재 버그 15개) audit.py에 4번 검사로 기계화했다.
- **ERROR 기준**: "읽기만 하고 아무도 set 안 하는 플래그"만 ERROR. 반대 방향(set만 하고 안 읽음)은 내러티브 기록용 플래그가 많아 보고하지 않는다.
- **empty_house 엔딩 재정의**: 원래 father.passed_away cast 플래그를 읽었으나 아버지 사망 이벤트가 존재하지 않아 영원히 도달 불가였다. 사망 메커니즘을 새로 만드는 대신 "30억 입성 + 관계 전무 + 아버지 비화해 = 빈 집 / 관계 전무 + 화해 = lonely_rich"로 분리해 기존 콘텐츠만으로 도달 가능하게 했다.
- **아버지 아크 구버전 삭제**: life_events.json의 arc_father_01~04(랜덤 풀 진행)와 arc_events.json의 arc_father_01~05(연출 진행)가 같은 스토리를 독립적으로 중복 진행했다. 연출 진행 쪽이 더 깊고(5단계) 결정적이므로 구버전 4종을 삭제. 좋은 텍스트를 잃지만 "아버지가 두 번 아프다"는 내러티브 파탄보다 낫다.
- **옛 설계 마일스톤 삭제**: 시작 20세/은퇴 55·65세 전제의 스토리 이벤트 7종(마흔다섯·쉰·예순 등)은 수정이 아니라 삭제. 33→38세 5년 구조에서는 대응 시점 자체가 없다.

## 2026-06-10 (6차 QA — 세이브·엔딩·아크 결과 내러티브)

- **SAVE_VERSION 3 / 직렬화 누락 수정**: `run_theme`·`unlocked_stat_thresholds` 두 필드가 `serialize()`에 없었다. 로드 후 런 테마가 항상 "자유런"으로 표시되고, 임계값 해금이 재발동되는 증상. whitelist 방식 직렬화 특성상 파싱 에러 없이 조용히 기본값으로 덮여 오랫동안 발견 안 됨. 구 세이브 호환은 `run_theme_categories`에서 테마를 역추론하는 compat 로직으로 처리.
- **엔딩 9종 활성화 — `finish_run()` 누락 원인**: 기존 엔딩 설계 문서에는 25개 엔딩이 기술돼 있었으나 `check_game_over()`에 실제 `finish_run()` 호출이 없었다. `creator_success`는 `creator_success_unlocked` 플래그를 체크했는데 해당 플래그를 SET하는 코드가 어디에도 없었다 — 드라마 피벗 과정에서 setter가 누락된 것. 더 단순한 `creator_viral` 플래그(이벤트 JSON에서 실제로 set됨)로 교체.
- **arc 결과 내러티브 구조**: `_last_opportunity_result`를 읽는 코드는 있었으나 실제로 분기에 활용되지 않았다. `win_flag`/`lose_flag` 키를 opportunity spec에 추가하여 결과를 플래그로 영속화하고, `_next_arc_id()`에서 해당 플래그를 읽어 follow-up 이벤트로 라우팅. result 이벤트에는 `min_turn:9999`를 설정해 랜덤 풀 진입 차단.
- **SimRun OPP 파라미터 불일치**: SimRun에서 사용하던 OPP 2개가 실제 게임 이벤트와 달리 음수 EV였다. 시뮬 승률이 실제 게임보다 낮게 측정되는 원인. 실제 아크/투자 이벤트 파라미터로 교체해 시뮬-게임 일치도 높임.

## 2026-06-10 (스팀 출시 데스크톱 폴리시)

- **export_presets.cfg 커밋**: 원래 `.gitignore` 대상이었으나, 이 프로젝트의 프리셋에는 서명 키/비밀정보가 전혀 없고 빌드 재현성(어느 머신에서나 `build.sh` 한 줄로 빌드)이 더 중요하므로 저장소에 커밋한다. 향후 코드사인 키를 넣게 되면 그때 분리한다.
- **Windows 단일 exe (embed_pck=true)**: Steam 업로드와 배포 단순화를 위해 pck를 exe에 임베드한다. `application/modify_resources=false`로 rcedit 의존성을 제거해 어느 환경에서나 export 가능하게 한다.
- **ESC는 시스템 메뉴 전용**: ESC가 모든 모달을 닫게 하면 이벤트 선택/월 결산 흐름이 의도치 않게 스킵될 수 있다(`_close_modal()`이 `_begin_month()` 등 사이드이펙트 보유). 따라서 ESC는 시스템 메뉴 열기/닫기에만 반응하고, 콘텐츠 모달은 명시적 버튼으로만 닫는다.
- **전체화면 설정 별도 파일**: `AudioManager`가 `gangnam_dream_settings.json`을 통째로 덮어쓰므로, 키 충돌(서로 키 누락 덮어쓰기)을 피해 디스플레이 설정은 `gangnam_dream_display.json`로 분리한다.
- **웹 빌드에서 전체화면 비활성**: 브라우저가 F11과 전체화면을 자체 관리하므로 웹 feature 감지 시 DisplayManager 입력 처리와 토글 UI를 모두 끈다.

## 2026-06-09 (이미지 생성 모델/프롬프트 파이프라인)

- **기본 이미지 모델**: 유저 지시에 따라 `tools/generate_assets.py`의 기본 모델을 `gpt-image-2`로 설정한다. 공식 문서에서 확인 가능한 모델명과 실제 계정 노출 모델명이 다를 수 있으므로 `--model` 옵션으로 `gpt-image-1.5`, `dall-e-3` 등으로 즉시 전환 가능하게 했다.
- **스타일 접두 방식**: 기존 배경 3종에서 추출한 `STYLE_SUMMARY`를 Master Style Guide보다 앞에 배치한다. 기존 캐릭터 포트레이트는 잘못된 스타일/연령대라 분석 기준에서 제외하고, 검증된 배경 분위기만 일관성 기준으로 사용한다.
- **생성 실패 정책**: 에셋 생성은 대량 작업이므로 한 이미지 실패가 전체 작업을 중단하지 않도록 경고 후 다음 에셋으로 진행한다. 최종 성공/스킵/실패 상태는 `assets/ASSET_INDEX.md`에 기록한다.
- **API 호출 방식**: `openai` SDK가 설치된 환경에서는 SDK를 우선 사용하되, 로컬 개발 환경에서 패키지 설치가 누락돼도 진행할 수 있도록 `requests` 기반 fallback을 둔다.
- **최종 스타일 피벗**: 전체 기존 이미지 세트가 여러 생성 세대가 섞인 상태라, 기존 특정 파일을 그대로 추종하지 않고 완전 애니/한국 만화풍 비주얼노벨 아트로 통일한다. 배경은 애니 배경 미술, 캐릭터는 serious manhwa/VN 포트레이트로 맞추며, photoreal/DSLR/피부 모공/카메라 보케는 금지한다.
- **실사용 에셋 우선순위**: 카드/칩처럼 코드에서 실제로 쓰지 않는 이미지보다 `ImageRegistry`, 이벤트 JSON, `SplashScreen.gd`가 직접 참조하는 에셋을 먼저 완성한다. 홀덤 카드/칩은 현재 `HoldemClub.gd`가 코드로 직접 그리므로, 실제 홀덤 디자인 이미지로 재작업하려면 먼저 UI 연결 방식을 결정한다.
- **주인공 나이 표현**: 게임의 핵심 시간축은 33세→38세 5년이므로 50대 초상화는 런타임 핵심 컷이 아니라 레거시/에필로그 슬롯으로 유지한다. 초반에는 기본·피로·결의 표정을 쓰고, `main_character_30s`는 실제 상승 상태에서만 사용한다.

## 2026-05-28 (RPG/Roguelike Pass)

- **행동력 소비 타이밍**: 투자 모달 오픈이 아닌 실제 매수·매도 실행 시에만 AP를 차감하도록 변경. 사용자가 시황을 분석하고 판단을 내리는 행위 자체에 비용을 부과하는 것은 게임 흐름을 방해한다고 판단.
- **무료 행동(free actions)**: 시장 분석(`_ap_market_analysis`)처럼 정보 습득에 해당하는 행동은 `free: true`로 표시해 AP=0에서도 사용 가능하게 함. 행동력 시스템이 정보 접근을 막는 구조는 피한다.
- **월별 크라이시스 확률**: 보너스 6% + 크라이시스 18% = 총 24% 발동률. 매달 확정 이벤트 외 추가 변수를 도입해 예측 불가능성을 높이는 로그라이크 핵심 루프. 3턴 이후 시작(온보딩 보호).
- **레버리지 마진콜 기준**: 포지션 가치가 원금 노출(leveraged_amount × 2)의 35% 이하일 때 강제청산. 실제 증거금 유지 비율(통상 10-20%)보다 완화된 값으로 설정 — 극단적 패널티는 게임오버보다 리커버리 전략을 강요하는 방향이 더 재미있다고 판단.
- **스탯 임계값 RPG 성장**: 30/50/70 세 단계로 설정. 초반 30은 빠른 달성으로 보람을 주고, 70은 장기 목표. 중간 50이 핵심 콘텐츠(무료 시장 분석, 레버리지)를 열어주는 분기점.
- **크래시 확률 상향 근거**: 테스터 피드백 "너무 무난함"에 대응. 시장이 예측 가능하면 전략적 긴장감이 없음. 더 잦은 폭락 위협이 레버리지/현금 비율 결정을 의미있게 만든다.
- **이벤트 반복 완화 전략**: 단기적으로는 최근 기억 창 확장(14→25)과 유니크 description으로 체감 반복을 줄임. 근본적 해결은 이벤트 pool 확장이나 동적 생성이지만 현 단계에서는 이 수준이 적절.

## 2026-06-01 (트레이트 제거 — 성향 시스템으로 일원화)

- **트레이트 시스템 폐기(option A)**: 인터랙티브 드라마로 피벗하면서 StartMenu의 트레이트 선택을 없앴고, 그 결과 `current_trait`은 실제로 어떤 패시브 분기와도 매칭되지 않는 죽은 값이 됐다. "흙수저 생존본능" 단일 트레이트를 살려 패시브를 부여하는 대안(option B)도 검토했으나, 드라마는 "선택한 특성"이 아니라 "플레이 중 쌓인 행동"으로 캐릭터성을 표현하는 방향이라 트레이트 개념 자체가 불필요하다고 판단. 변수·분기·데이터(`traits.json`)·메타 해금까지 전면 제거.
- **성향(tendency)으로 일원화**: 직장/투자/창업 성향을 행동으로 누적하고 임계점(1위 ≥12, 2위와 격차 ≥4)에서 '자각'하며 1회 패시브를 부여하는 시스템이 트레이트의 역할(시작 정체성/패시브)을 대체한다. 선택지가 아닌 누적 행동이 정체성을 만든다는 드라마 톤과 일치.
- **메타 해금 경계**: 트레이트 해금만 제거하고 업적(achievement)·칭호(title) 해금은 그대로 유지. 칭호 중 "인맥왕"·"번아웃 생존자"는 옛 트레이트와 이름만 겹칠 뿐 별개 시스템이라 보존.
