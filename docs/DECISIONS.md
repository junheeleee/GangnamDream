# Gangnam Dream Decisions

## 2026-06-15 (미니게임 독립 품질 기준)

- **품질 기준 상향**: 경마·홀덤·투자·카지노는 보조 모달이 아니라 강남드림의 대중적 재미를 담당하는 핵심 게임이다. 각 미니게임은 "이것만 떼어도 작은 유료 게임으로 팔 수 있나?"를 목표 기준으로 삼는다.
- **강원랜드 범위 포함**: 새로 구현 중인 강원랜드 계열 게임 전체를 이 기준에 포함한다. 현재 블랙잭·바카라가 대상이며, Claude가 이후 추가하는 카지노 게임도 룰 구현 직후 반드시 연출/사운드/세션 UX 품질 패스를 거친다.
- **상업 품질 기준**: 유저 기준은 "플래시게임 수준이 아니라 2만원짜리 게임처럼 보여야 한다"이다. 따라서 미니게임 완료 판정은 룰 작동이 아니라 테이블 레이아웃, 조작 반응, 애니메이션, SFX, 승패 연출, 세션 기록, 반복 플레이 감각까지 포함한다.
- **우선순위**: 룰의 복잡도를 먼저 늘리지 않는다. 플레이어가 5초 안에 느끼는 손맛, 즉 입력 반응, 애니메이션, 사운드, 승패 연출, 숫자 변화의 타격감, 재도전 욕구를 먼저 올린다.
- **경마 1차 적용**: 경마는 베팅홀 정적 화면에서 트랙 배경으로 전환하고, 말 실루엣 위에 기수/새들, 흙먼지, 속도선, 선두 교체 실황을 얹는다. 전용 고해상도 스프라이트 시트와 말발굽/관중 SFX는 다음 품질 패스의 대상이다.
- **홀덤 1차 적용**: 홀덤은 중앙 팟 표시, 칩 버스트, 페이즈/액션 배너, 카드 공개 펄스를 추가해 텍스트 중심 모달에서 테이블 게임에 가까운 감각으로 올린다. 다음은 칩이 실제 위치로 이동하는 애니메이션, 딜러 사운드, 쇼다운 슬로모션/핸드랭크 배너다.
- **투자 1차 적용**: 스캘핑은 캔들, 진입/청산 마커, 손익 배너로 "내가 어느 타이밍에 맞았는지/틀렸는지"를 보이게 한다. TradingFloor는 평균단가선과 체결 피드백으로 자산 운용 화면도 게임처럼 반응하게 한다.
- **확장 순서**: 투자 프레젠테이션 1차 → 강원랜드 블랙잭/바카라 실기 QA와 카드·칩·딜러 연출 → 경마/홀덤 전용 SFX·스프라이트 고도화 순서로 진행한다. 전부 한 번에 넓히기보다 하나씩 "팔 수 있는 감각"까지 끌어올린다.

## 2026-06-15 (이미지 라우팅과 게임감 연출의 경계)

- **장소 키워드는 카테고리보다 우선**: 이벤트 category가 `investment`/`gambling`이어도 본문이 카페·회사·부동산·편의점·지하철·홀덤·경마를 명확히 말하면 해당 장소 배경을 먼저 쓴다. 플레이어는 장르 카테고리가 아니라 현재 장면을 본다.
- **하지만 전부 자동 수정하지 않는다**: 회식, 회상, 전화, 뉴스 확인처럼 "말하는 주제"와 "실제 장소"가 다를 수 있다. 그래서 semantic audit 잔여 REVIEW는 빌드 실패가 아니라 수동 QA 리스트로 둔다.
- **게임감은 새 시스템보다 반응 레이어부터**: 지금 강남드림은 선택 결과, 도박 승패, 큰 돈 변동의 감각이 약했다. 대규모 룰 개편보다 플래시/흔들림/펄스/SFX를 얹는 쪽이 기존 콘텐츠를 보존하면서 체감 품질을 빠르게 올린다.

## 2026-06-13 (런타임 배경 의미 매핑 우선순위)

- **문제 진단**: 에셋 파일 자체가 정합성을 통과해도, 런타임 배경 선택이 `social → cafe`, `health → hospital` 같은 broad category를 먼저 적용하면 텍스트와 화면이 충돌한다. 실제 QA에서 `집들이` 결과 지문의 "방 안을 둘러봤다"가 카페/거리 배경처럼 보이고, 운동/헬스장 지문이 직전 병원 배경을 물고 갈 수 있음을 확인했다.
- **결정**: 배경 자동 추론은 broad category보다 구체적인 장소 의미를 먼저 본다. `집들이`/방/옆 건물/현재 주거는 housing background, `gym`/`exercise`/헬스장/운동은 운동 계열 배경, 병원은 명시 hospital 태그나 병원·의사·검진·응급실 같은 의료 텍스트가 있을 때만 선택한다.
- **추론 범위**: 배경은 현재 장면의 `id`, `title`, `description`, `category`, `tags`로 결정한다. 선택지/결과문까지 섞으면 아직 고르지 않은 선택지의 장소가 시작 배경을 오염시킬 수 있으므로 배제한다.
- **런타임 일원화**: MainGame과 StoryMode는 같은 `ImageRegistry.infer_background_id()` 규칙을 사용한다. 루틴 비네트는 이벤트 객체가 아니므로 별도 비네트 배경 선택을 갖고, 직전 이벤트 배경을 상속하지 않는다.
- **후속**: `gym`은 현재 병원 오매핑 방지를 위해 운동 계열 safe fallback으로 연결되어 있다. Steam 최종 전에는 `gym_interior` 전용 배경을 생성해 alias를 실제 헬스장 배경으로 교체한다.

## 2026-06-13 (P3 오디오 생성/검증 기준)

- **문제 진단**: 외부 음악 생성 서비스 결과물을 기다리면 오디오 패스가 막히고, 기존 파일 중 `bgm_gosiwon.ogg`는 Theora video로 인식되는 등 런타임 안정성 위험이 있었다. 또한 코드에서 `buy`, `sell`, `tab_open` SFX를 호출하지만 `AudioManager`에는 매핑이 없어 해당 액션이 무음이었다.
- **결정**: 현재 production P3 패스는 `tools/generate_audio_assets.py`의 deterministic local synthesis로 생성한다. BGM은 Ogg Vorbis 44100 Hz stereo, SFX는 WAV 44100 Hz mono를 기준으로 한다. 외부 작곡/효과음으로 교체하더라도 같은 파일명, 같은 runtime key, 같은 loop 정책을 유지해야 한다.
- **검증 기준**: `tools/AudioAssetCheck`가 `BGMPlayer.TRACKS`와 `AudioManager._SFX_FILES` 전체를 `AudioStream`으로 로드할 수 있어야 한다. 코드에서 새 `AudioManager.play("...")` 키를 추가하면 먼저 `_SFX_FILES`에 매핑하고 이 체크를 통과시킨다.
- **루프 정책**: menu/goshiwon/main/apartment/crisis/ending BGM은 import loop ON, victory는 one-shot이므로 loop OFF다.

## 2026-06-13 (Steam 키아트 타이포 합성 규칙)

- **문제 진단**: 이미지 생성 모델에 게임 제목을 직접 넣기 요청하면 한글/영문 로고가 깨지거나 비슷한 글자처럼 왜곡될 위험이 높다. Steam 캡슐은 작은 크기에서 제목 가독성이 매출에 직접 영향을 주므로, 그림은 좋아도 텍스트가 깨지면 production 자산으로 부적합하다.
- **결정**: 마스터 키아트는 텍스트 없이 생성하고, Steam 캡슐/헤더의 `GANGNAM DREAM` / `강남드림` 제목은 로컬 폰트로 후합성한다. 이렇게 하면 이미지 생성 품질과 타이포 가독성을 분리해 관리할 수 있다.
- **적용**: `gangnam_dream_keyart_rooftop.png`는 1920x1080 textless master로 교체했고, `steam_capsule_main.png`, `steam_header.png`, `steam_capsule_small.png`는 같은 마스터에서 크롭한 뒤 로컬 폰트 타이틀을 얹어 제작했다.

## 2026-06-13 (공공장소 배경 실루엣 허용 규칙)

- **문제 진단**: "배경은 인물 없는 장소" 원칙을 모든 장소에 절대 적용하면 PC방, 경마장, 홀덤 클럽, 식당, 도서관처럼 원래 사람이 있어야 자연스러운 공간이 비어 보인다. 반대로 이전 배경처럼 얼굴/손/전경 인물이 선명하면 반복 포트레이트와 충돌하고 특정 장면 CG처럼 읽힌다.
- **결정**: 배경 원칙을 "반복 인물 금지"로 정교화한다. 고시원, 가족집, 병원실, 투자 책상처럼 정합성이 민감한 공간은 person-free를 유지한다. 공공장소는 작고 어두운 익명 실루엣, 뒷모습, 모니터/가구 뒤에 가린 seated figure, 군중 텍스처를 허용한다.
- **실패 기준**: 얼굴이 보이거나, 전경에 크게 서 있거나, 손/팔이 장면의 주체가 되거나, 한 인물이 주연/조연처럼 읽히면 그 이미지는 reusable background가 아니라 CG 후보로 판정한다.
- **적용**: `library`, `restaurant_korean`, `pc_bang_interior`, `racetrack_betting_hall`, `holdem_club_interior`, `hometown_train_station`, `seoul_rainy_street`를 이 기준으로 교체했고, 배경 감사 상태를 PASS로 갱신했다.

## 2026-06-12 (CG 런타임 표시 규칙)

- **StoryMode CG 우선순위**: 이벤트에 `cg`가 있으면 background 추론보다 먼저 전체화면 CG를 표시한다. CG는 이미 특정 사건의 인물+공간을 포함하므로 별도 포트레이트 프레임을 숨긴다. 이름표와 텍스트 박스는 유지해 대사/서술 흐름은 그대로 읽히게 한다.
- **엔딩 CG 이중 표시**: 엔딩 모달은 화면 중앙을 크게 덮기 때문에 CG를 배경으로만 깔면 핵심 장면이 가려진다. 엔딩 `cg`는 배경 이미지로도 쓰고, 모달 내부에 와이드 프리뷰를 한 번 더 넣어 플레이어가 반드시 컷을 보게 한다.
- **헤드리스 검증**: `tools/CGRuntimeCheck`는 MainGame 전체 월 루프를 띄우지 않고, StoryMode 실제 이벤트 렌더와 MainGame CG 경로/프리뷰 헬퍼를 직접 검증한다. 장면 전환과 월 이벤트 추첨이 QA 도구를 흔들지 않게 하기 위해서다.

## 2026-06-12 (인게임 크롭 QA 방식)

- **크롭 QA는 CPU 합성 툴로 고정**: Godot headless dummy renderer에서는 SubViewport 스크린샷 텍스처가 비어 실제 렌더 캡처가 안정적으로 불가능했다. 크롭 QA의 목적은 "현재 UI 수학에서 어떤 부분이 잘리는가"이므로, `tools/VisualCropQA`가 PNG를 직접 읽고 MainGame/StoryMode/CG의 배치/스케일 규칙을 CPU로 합성하는 방식으로 전환했다. 이렇게 하면 로컬/CI/headless 어디서든 같은 결과가 나오고, 최종 라이브 UI QA는 별도 실제 실행 체크로 보완한다.

## 2026-06-12 (late_night 배경 remap)

- **문제 진단**: `late_night_room.png`는 큰 창문과 다른 침대/책상 배치를 가진 별도 방이다. 고시원 밤, 정신력, 야간 고민 이벤트에서 이 배경이 뜨면 유저가 지적한 "고시원 구조가 계속 바뀌는" 문제가 재발한다.

- **후속**: 정말 원룸/아파트 밤 장면이 필요하면 `oneroom_apartment.png` 계열을 명시적으로 사용하고, 고시원/초반 정신력 이벤트는 반드시 `goshiwon_room.png` 구조를 유지한다.

## 2026-06-12 (반복 보조 NPC 투명화)

- **결정**: 이름/ID로 반복 등장하는 조연은 주연급과 같은 투명 포트레이트 규칙을 적용한다. 배경 포함 예외는 정말 1회성 엑스트라에만 허용한다.
- **정본 교정**: 박성준은 금융권 연락처가 아니라 34세 고교 친구이자 9급 공무원 3년차로 시각화한다. 팀장과 헷갈리지 않도록 안경을 제거하고, muted cardigan/jacket, 체크 셔츠, ID 목걸이로 구분한다.
- **구분성 보강**: 팀장은 흰 셔츠·넥타이·팔짱·안경의 권위 실루엣을 유지한다. 성준은 부드러운 얼굴, 안경 없음, 공무원 ID, 체념 섞인 미소로 구분한다.

## 2026-06-12 (김민준 직업별 의상 포트레이트)

- **결정**: 김민준의 평상시/결의/수트 계열 포트레이트는 `ImageRegistry.get_player_context_portrait()`에서 직업 티어와 카테고리로 동적 선택한다. 무직은 기본복, survival 직업은 알바/캐주얼, 일반 사무/교육/기술직은 사무직, 대기업·금융·영업·티어3+는 정장으로 표시한다.
- **감정 우선순위**: 충격·마일스톤·위험 상태는 의상보다 감정 전달이 중요하므로 shocked/happy/tired 포트레이트가 우선한다. 추후 품질 고도화 시에는 직업 의상×감정 매트릭스를 별도 제작한다.
- **레거시 처리**: `main_character_30s.png`는 방 배경이 박혀 있으므로 default runtime status portrait에서 제외한다.

- **신용등급 도입 (유저 지시)**: 고정 한도·금리 대신 신용점수(고용·근속·소득·순자산·평판 − 부채비율·바닥이력) → 1~10등급이 한도·금리를 결정. **변동금리**를 택한 이유: 대출 시점 고정금리는 "빌리고 나면 끝"이라 긴장이 없다. 매달 현재 등급으로 이자를 재계산하면 실직·자산 손실이 보유한 빚의 이자 상승으로 즉시 전이 — 현실의 "빚의 악순환"이 메커니즘으로 작동하고, 등급 관리(근속·자산·상환)가 지속적인 인센티브가 된다. 저장 데이터도 원금만 있으면 돼서 세이브 호환이 단순해지는 부수 이점.

## 2026-06-11 (아크와 자원 게임의 역할 분리)

## 2026-06-01 (트레이트 제거 — 성향 시스템으로 일원화)

- **트레이트 시스템 폐기(option A)**: 인터랙티브 드라마로 피벗하면서 StartMenu의 트레이트 선택을 없앴고, 그 결과 `current_trait`은 실제로 어떤 패시브 분기와도 매칭되지 않는 죽은 값이 됐다. "흙수저 생존본능" 단일 트레이트를 살려 패시브를 부여하는 대안(option B)도 검토했으나, 드라마는 "선택한 특성"이 아니라 "플레이 중 쌓인 행동"으로 캐릭터성을 표현하는 방향이라 트레이트 개념 자체가 불필요하다고 판단. 변수·분기·데이터(`traits.json`)·메타 해금까지 전면 제거.
- **성향(tendency)으로 일원화**: 직장/투자/창업 성향을 행동으로 누적하고 임계점(1위 ≥12, 2위와 격차 ≥4)에서 '자각'하며 1회 패시브를 부여하는 시스템이 트레이트의 역할(시작 정체성/패시브)을 대체한다. 선택지가 아닌 누적 행동이 정체성을 만든다는 드라마 톤과 일치.
- **메타 해금 경계**: 트레이트 해금만 제거하고 업적(achievement)·칭호(title) 해금은 그대로 유지. 칭호 중 "인맥왕"·"번아웃 생존자"는 옛 트레이트와 이름만 겹칠 뿐 별개 시스템이라 보존.
