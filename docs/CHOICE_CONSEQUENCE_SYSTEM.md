# CHOICE_CONSEQUENCE_SYSTEM.md — 표현·기억·결정과 5장 인과 원장

> 이 문서가 **선택의 종류, 선택이 저장되는 방식, 다섯 챕터를 건너 결과를
> 회수하는 규칙**을 소유한다. 장면의 길이와 연출 등급은
> [`SCENE_TIER.md`](SCENE_TIER.md), 인물·세계 사실은
> [`STORY_BIBLE.md`](STORY_BIBLE.md), 엔딩 가족은
> [`ENDING_CONTRACT.md`](ENDING_CONTRACT.md)가 각각 소유한다.

## 0. 현재 판정 — 재료는 있으나 하나의 체계는 아니다

24주 V2에는 선택·의무·관계 기억·미선택 결과·지연 후속을 출처와 함께
보존하는 영수증이 있다. 240주 본편에도 `flags`, 관계 단계·호감도,
`route_orthodox/unorthodox`, `moral_tint`, `deferred_events`, 개별 콜백이
존재한다. 따라서 새 게임을 처음부터 다시 만드는 문제는 아니다.

그러나 현재 본편의 약속 원장은 최근 16건만 남고, 지연 사건은 대체로 사건 ID와
발화 주차만 보존한다. `story_rules.json`의 많은 사실 계약은 정적 감사용이며,
런타임에서 다섯 장의 선택을 한 원장으로 모으지 않는다. 엔딩도 구체 플래그와
수치의 우선순위 사슬을 읽지만, 다섯 장의 원인과 비용을 고르게 읽지는 않는다.

따라서 현재 구조는 **스노우볼을 만들 부품은 충분하지만, 1장의 선택이 5장의
마지막 서명까지 굴러간다고 보장하는 체계는 부족하다.** 아래 규칙은 기존 부품을
버리지 않고 역할을 나눠 연결한다.

## 1. 선택은 세 종류다

| 종류 | 플레이어가 하는 일 | 저장 | 후속 의무 |
|---|---|---|---|
| **표현 선택** | 민준의 말투·솔직함·침묵·행동 온도를 정한다 | 원칙적으로 없음 | 같은 장면 안에서 서로 다른 대답·연기 뒤 자연스럽게 합류 |
| **기억 선택** | 한 사람에게 실제로 무엇을 말하거나 했는지 남긴다 | 영구 `receipt` | 이름을 가진 후속 장면·보스·엔딩 독자 최소 1개 |
| **결정 선택** | 길을 닫거나 불가역 사실·관계 단계·흉터를 만든다 | 배타적 typed fact 또는 scar | 다음 장의 참가자·문장·위협·가용 행동을 바꾸거나, 5장이라면 엔딩·사람들의 이후가 그 사실을 직접 읽음 |

### 표현 선택

표현 선택은 수치가 없다는 이유로 가짜 선택이 아니다. 플레이어가 민준의
목소리를 쓰고 상대가 그 말에 맞게 반응하면 그것이 결과다.

예:

```text
다은: “민준씨, 잘 지냈어요?”

“네, 잘 지냈어요.”
→ “다행이네요. 얼굴이 조금 좋아 보여요.”

“아뇨. 어제 잠을 설쳤네요.”
→ “그래요? 오늘은 커피 말고 따뜻한 걸 드릴까요?”
```

두 경로는 손님 입장, 계산대 호출, 장소 이동처럼 자연스러운 행동에서 다시
합류한다. 선택 직후 같은 문장을 출력하거나, 의미 없는 `mental +1`을 붙여
차이를 꾸미는 것은 금지한다. 고유 반응의 길이는 할당하지 않고, 두 선택의
온도와 상대의 반응 차이가 플레이어에게 분명히 읽힐 만큼만 이어 간다.

### 기억 선택

기억 선택은 선악 점수가 아니라 `누가 / 언제 / 무엇을 / 어떤 비용으로` 했는지를
남긴다. 독자는 그 사실을 직접 언급하거나, 인물의 행동·부재·선택 가능성으로
회수한다. 독자 없는 영수증은 쓰지 않는다.

### 결정 선택

결정 선택은 점수 몇 점으로 상쇄할 수 없다. 대포통장을 빌려 준 사실, 아버지의
전화보다 돈을 택한 사실, 누군가를 서류의 수단으로 쓴 사실처럼 정확한 사건은
정확한 사실로 남는다. 반복 습관 점수는 이 사실을 지우지 못한다.

## 2. 저장 역할을 섞지 않는다

- **fact/flag:** 생사·관계 단계·서명·배신처럼 참/거짓 또는 제한된 enum인 사실.
- **receipt:** 원인 선택, 배우, 주차, 비용, 미룬 길, 예정된 독자를 가진 기억.
- **pattern accumulator:** 약속을 지킴, 사람을 수단화함, 가족을 회피함, 위험을
  확대함처럼 반복 행동의 모양. 한 번의 중대한 사실을 덮어쓰지 않는다.
- **MORAL_TINT:** 세계를 보는 색과 산문·연기의 변주. 엔딩을 혼자 고르는
  도덕 점수가 아니다.
- **관계 상태:** 단계·호감도만이 아니라 인물별 기억 영수증을 함께 읽는다.
- **물질 상태:** 돈·직업·몸·주거는 실제 비용과 선택 가능성을 결정한다.

같은 선택을 flag, receipt, route 점수에 근거 없이 세 번 복제하지 않는다.
정확한 사실은 fact, 인과 설명은 receipt, 반복 습관만 accumulator가 소유한다.

## 3. 장기 원장 최소 스키마

아래는 구현 전에 고정할 개념 스키마다. 실제 키 이름은 저장 이관 오더에서
검증하되 역할을 합치지 않는다.

```text
story_ledger
  schema_version
  facts
    <fact_id>: { value, source_receipt_id }
  receipts
    <receipt_id>:
      { turn, source_chapter, event_id, choice_id,
        kind: memory|decision, scene_tier,
        actors, tags, costs, forgone,
        readers: [{ id, horizon, status }] }
  patterns
    { kept_promises: [{ source_receipt_id, chapter }],
      used_people: [...], avoided_family: [...],
      owned_consequences: [...], escalated_risk: [...] }
  chapters
    <1..5>:
      { receipt_ids, boss_input_ids, boss_decision_id,
        carryovers, opening_payoff_status }
  scheduled
    <contract_id>:
      { source_receipt_id, due_window, target_event, status, payload }
```

표현 선택은 이 원장에 넣지 않는다. 다만 작가가 이후에 정확히 회수할 이유를
명시한 표현만 기억 선택으로 승격할 수 있다.

pattern은 증거 receipt를 보존하며 모든 축을 합친 숨은 도덕 총점을 만들지
않는다. 엔딩이나 장면은 필요한 pattern의 출처와 챕터 분포를 읽는다.

### 60개월 장면 배치 정본

플레이어는 별도 월간 행동판에서 약속을 고르지 않는다. 돈 벌기, 연락하기, 쉬기,
투자하기처럼 서사를 바꾸는 행동은 그 행동이 실제로 벌어지는 `StoryMode` 장면의
표현·기억·결정 선택이 소유한다. `주력/함께`, 같은 축 여유, 월간 후보 카드,
미룸 제출 화면을 이름만 바꿔 되살리지 않는다.

`content/meta/story_map.json`은 M01~M60의 시간 순서, 장별 질문, 장면 beat와
불가역 결정의 작가용 배치 입력이다. 현재 파일의 `commitments`, `loop_contract`,
`carryover_slots`에 남은 월간 선택판 가설은 반려된 역사 자료이며 제품 런타임·UI·
완성도 집계가 읽지 않는다. 데이터 삭제와 스키마 정리는 별도 이관에서 하되,
그 전에도 새 consumer를 붙이지 않는다. `narrative_spine.json`은 다섯 장의 거시
질문과 모티프를, `story_rules.json`은 enum 사실과 구현된 사건 조건을 소유한다.

한 달의 기본 흐름은 아래 네 단계다.

1. 시간, 앞선 fact/receipt, 돈·직업·몸·관계 상태가 다음 장면과 참가자를 고른다.
2. 장면 안에서 민준이 지금 할 구체 행동이나 말을 고른다.
3. 선택의 즉시 결과와 이름 있는 후속 fact/receipt를 원자적으로 적용한다.
4. 장면이 끝나면 달력, 수입·월세·이자, 몸·마음과 자동 루틴이 흐른다.

전환막이나 월말 표면은 이미 일어난 시간과 정산을 읽기만 한다. 다음 달 행동을
고르거나 최적화 정보를 제출하는 두 번째 선택층이 아니다. 모든 달에 억지 결정을
넣지 않는다. 갈등을 변화시키지 않는 달은 표현 선택이나 무선택 장면으로 흐를 수
있고, 이름 있는 문을 닫는 달만 기억·결정 선택을 요구한다.

행동을 소유하는 기억·결정 선택은 `지금 무엇을 한다`는 동사, 당장 치르는 시간·
돈·몸·관계 비용, 함께 할 수 없는 대안, 이름 있는 후속 독자를 가진다. 고르지 않은
길은 그 장면이 명시한 부재·마감·상대의 반응으로만 돌아오며, 카드마다 숨은 전역
벌점을 쌓지 않는다. 정확한 미래 이득·닫힐 사건·관계 단계는 선택 전에 해설하지
않고 실제 장면이 도착했을 때 처음 드러낸다.

자동 생계·회복·직업 루틴은 선택처럼 연출하지 않는다. 그 결과는 다음 장면의
잔액·몸·가용 행동을 바꾸는 생활 조건이다. 작성형 아크가 같은 시간의 갈등을
소유하면 일반 AP나 월간 연락 카드를 다시 열지 않는다. 첫 만남 이후 관계 진전은
민준이 먼저 연락하거나 찾아가는 실제 장면 선택, 또는 그 선택에 근거한 상대의
회신이 있어야 하며 호감도만으로 자동 진행하지 않는다.

경로에 따라 루트나 참가자가 달라질 때는 승인된 story fact, 앞선 receipt,
유한한 route enum 중 하나가 `base + fallback`을 닫는다. `@role` 참가자는 이름표
문자열로 추측하지 않고 고정 인물, enum 값, memory/decision/scheduled receipt의
typed actor binding을 읽는다. 존재하지 않는 연인·초대·생존 인물을 선택지에
내놓지 않는다.

장간 불가역 결정은 아래 일곱 개로 닫는다.

- 첫 불법 제안
- 아버지 병실 문
- 상철 진실의 처리
- 재혁 보증의 처리
- 연인과의 약속
- 타인의 이름을 계약에 쓴 방식
- 아버지와의 마지막 연락

챕터 결산은 원본 receipt를 보존하면서 다음 장 첫 장면에 보스 결정 하나와 가장
관련 있는 미해결 scheduled/memory receipt 최대 둘만 넘긴다. 과거
`protected_commitment`, `expired_obligation`, `open_debt` 슬롯명은 월간 선택판
저장의 이관 별칭일 뿐 새 런타임 계약이 아니다. typed reference는 계속
`kind + source_receipt_id + 선택적 actor_id`를 가져 누구의 어느 선택인지 잃지
않는다. 독자 없는 기억은 만들지 않는다.

랜덤 사건은 비용과 충돌을 바꿀 수 있지만 선택지를 이유 없이 닫지 않는다.
A→B와 B→A가 기한·선행조건·사람 반응을 실제로 바꿀 때만 장면 안에서 순서를
묻는다. M59 실행과 M60 마지막 서명도 월간 commitment 상태가 아니라 각각의
StoryMode 결정과 그 exact receipt가 소유하며, W240 장면 뒤 엔딩 독자가 직접
`signed/leave_blank`를 읽어 M61 없이 닫는다.

## 4. 스노우볼 규칙

1. **기억에는 이름 있는 독자가 있다.** 장면 안, 같은 장, 다음 장, 후반 결산
   중 실제 horizon을 선언하고 독자별 `pending/consumed/retired` 상태를 남긴다.
2. **결정은 누적 독자를 가진다.** 즉시 결과로 끝나지 않고 이후 챕터와 보스·
   엔딩 중 이름 있는 독자가 형태를 바꿔 회수한다. 5장의 결정은 다음 장 대신
   최종 장면·사람들의 이후·에필로그가 소비한다.
3. **챕터 보스는 누적 과거를 읽는다.** 이번 장의 기억뿐 아니라 이전 장에서
   넘어온 핵심 carryover와 불가역 결정을 함께 읽고, 보스 결정은 다음 장 첫
   소설 시퀀스를 바꾼다. 5장 보스는 엔딩 계층을 바꾼다.
4. **한 장면의 역사 입력은 작고 명시적이다.** 모든 조합을 별도 장면으로 만들지
   않는다. 원칙적으로 가장 관련 있는 기억 둘과 결정 하나까지만 직접 읽고,
   더 오래된 묶음은 앞 장의 carryover가 요약해 전달한다. 돈·몸·직업 같은
   현재 물질 상태는 분기 입력이 아니라 장면의 기본 현실이므로 이 셋에 넣지 않는다.
5. **공통 척추로 합류하되 기억을 지우지 않는다.** 큰 장면의 목적지는 같아도
   도착한 인물, 첫 문장, 열린 선택, 마지막 여운이 달라질 수 있다.
6. **작은 선택은 자동으로 5장까지 끌고 가지 않는다.** 즉시 반응으로 충분한
   것은 표현 선택으로 닫는다. 반복되거나 인물·상징의 핵심이 된 것만 기억으로
   승격한다.
7. **이름 있는 미선택만 장기 원인이 된다.** 이후 계약이 있는 약속 거절, 기한
   상실, 기다리게 한 사람은 선택한 길과 같은 출처·주차를 가진 영수증으로
   남긴다. 단순 표현 선택과 독자 없는 제안은 장면 또는 월간 기록에서 닫는다.
8. **carryover는 조용히 사라지지 않는다.** 다음 장으로 넘길 때 원형 유지,
   변형, 해결, 은퇴 중 하나를 선언한다. 1장의 핵심 상징·결정은 endgame
   horizon을 가진 독자가 3장 또는 5장에서 형태를 바꿔 읽는다.

## 5. 챕터 결산

- 장기 기억은 이후 독자가 있는 소수만 승격하고, 나머지는 표현 선택이나 현재
  상태로 닫는다. 장간 불가역 결정은 위 일곱 사실만 사용하며 새 장기 사실을
  장면마다 발명하지 않는다.
- 표현 선택은 장면 호흡에 따라 쓰되, 같은 질문을 말만 바꿔 반복하지 않는다.
- 챕터 마감은 그해의 핵심 기억, 보스 결정, 미해결 carryover를 한 묶음으로
  잠근다. 묶음의 크기는 실제 독자와 장면 복잡도로 판정한다.
- 다음 장 오프닝은 그 carryover를 소비하기 전까지 공통 소개문으로 덮지 않는다.

플레이어에게 이 원장을 점수표로 보여 주지 않는다. 연말에는 숫자 대신 실제로
남은 물건·문장·사람·미룬 약속을 보여 준다.

## 6. 장면 안의 선택 배분

비트 수, 링크 수, 표현 선택 수에는 공통 목표를 두지 않는다. 5비트가 맞는
장면도 30비트가 필요한 장면도 있다. 숫자를 먼저 정하고 대사나 클릭을 채우면
필러가 된다.

한 장면은 한 번 진입한다. 구현상 표현 분기와 합류를 위해 여러 링크를 쓰더라도
같은 시간·장소·질문에서는 제목·대화 로그·음악·배경을 이어 간다. 짧은 반응을
각각 새 이벤트 카드로 띄우지 않는다.

대신 장면의 기능을 끝까지 쓴다.

- **대화·관계 정점:** 구체적인 도착, 실제 왕복, 상대의 의도 변화, 표현 선택에
  대한 고유 반응, 압박의 전환, 결정, 상대 반응, 장면 뒤의 여운.
- **솔로·추론·의식 정점:** 실제 증거와 몸의 행동, 서로 충돌하는 해석, 능동적
  선택, 실행, 정확한 영수증, 다음 질문.
- **챕터 보스:** 누적 과거의 회수, 두 가치 이상의 충돌, 압박 상승, 전환 또는
  반전, 불가역 결정, 경로별 결과, 다음 장 carryover 또는 엔딩 청구.

한 기능이 여러 비트를 요구할 수 있고 여러 기능이 한 비트에서 충돌할 수도
있다. 표현 선택은 자연스러운 질문이 있을 때 원하는 만큼 쓰되, 쓰면 반드시
고유 반응 뒤 합류한다. 기억과 결정은 실제 미래 독자가 있을 때만 쓴다.

## 7. 현재 콘텐츠에 적용하는 예

### 24주 첫 청구서 — 세 층을 한 장면에서 섞지 않는 기준

- 플레이어에게는 한 장면으로 보인다. 17:52 책상에서 시작해 고른 행동의
  실제 장소와 시간으로 이동한 뒤 같은 수첩 장부로 돌아오며, 제목·대화 기록·
  BGM은 새 장면처럼 재시작하지 않는다. 배경·앰비언스는 경로 사실에 맞게
  바뀌고 갤러리와 올해의 장면에는 진입 조각 하나만 등록한다.
- 세 표현 선택은 민준의 솔직함과 행동 온도를 고르고 각기 다른 지문 뒤
  합류한다. `GameState.serialize()`, 약속, 영수증, 호감도, Moral Tint를
  바꾸지 않는다.
- 이 장면의 기존 여덟 후보 중 실제 자격이 있는 2~4개 사이에서 고른
  하나만 바꾼다. 선택 인덱스·효과·영수증은 기존 계약을 보존한다.
- 장부는 `끝낸 일`, `미룬 약속`, `마감이 지나 더는 할 수 없는 일`을 같은 단어로
  뭉개지 않는다. 각각의 출처와 후속 독자가 나중 장면에서 같은 사실을 읽는다.
- 회상은 당시 상태 스냅숏을 읽는 별도 로컬 문맥이며 현재 런의 원장을 바꾸지
  않는다. 복원할 증거가 없는 옛 완료 저장에는 기억을 발명하지 않는다.

이 예의 세 표현, 여덟 후보, 세 내부 조각은 다른 정점에 복사할 수량 기준이
아니다. 장면마다 필요한 기능과 실제 미래 독자가 선택 층과 길이를 정한다.

### 첫 불법 제안 → 마지막 서명

- 1장: 대포통장 제안의 정확한 선택을 결정 fact와 receipt로 남긴다.
- 2장: 상철·재혁이 민준의 과거 행동을 아는 것이 아니라, 민준이 비슷한 호의를
  받아들이거나 경계하는 방식이 달라진다.
- 3장: 보증 PDF와 타인의 돈 앞에서 1장의 선택을 거울로 회수한다.
- 4장: 그 방식의 비용을 몸·가족·관계 중 실제로 닿은 축에 청구한다.
- 5장: 마지막 서명의 열린 선택과 산문, 사람들의 이후가 그 원장을 읽는다.

### 현수의 문

- 먼저 찾아갔는지, 기다리게 했는지는 기억 receipt다.
- 현수가 실패를 말하는 문장과 후일 재회의 태도가 달라진다.
- 재혁 경고가 성립할 때 현수의 말이 도착하는 방식과 신뢰도가 달라질 수 있다.
- 마지막 `사람들의 이후`는 단순 `met=true`가 아니라 이 기억을 읽는다.

이 구조는 가지를 끝없이 늘리는 트리가 아니라, 같은 소설 척추가 플레이어의
기억을 가지고 눈덩이처럼 무거워지는 **분기 스택**이다.

## 8. 엔딩에 제공하는 입력

정확한 엔딩 가족·귀결·사람들의 이후 판정 순서는 `ENDING_CONTRACT.md`가
소유한다. 이 원장은 그 판정에 다음 언어 독립 입력을 제공한다.

- 파산·사망·관계 생사 같은 현재 사실
- 목표 도달·미도달과 실제 물질 상태
- 배신·서명처럼 점수로 상쇄할 수 없는 불가역 결정
- 출처와 챕터 분포가 남은 반복 pattern
- 인물별 기억과 미선택 영수증, 소비되지 않은 carryover

엔딩은 `moral_tint >= N` 하나나 마지막 관계 불리언 하나로 이 입력 전체를
대체하지 않는다. 정확한 결정은 정확한 사실로, 반복된 삶의 모양은 여러 장의
출처가 있는 pattern으로 읽는다.

### 5장 M49~M60 exact receipt 계약

M49~M55 투자 기준 경로는 로케일 중립 `Chapter5CausalRoute` 원장 하나가 소유한다.
W195 진입은 실제 투자형 정체성·`route_invest`·20억원 이상 자산 구간과
이어진 상철·다은·민서·재혁 관계를 모두 요구한다. 첫 장면을 보여 주기 전에
`investment_property`, `at_least_2b`, 역할별 실제 배우를 exact entry로 고정하며,
이후 시장이나 관계가 움직여도 이미 시작한 세로줄의 정체성을 다시 추론하지 않는다.
각 선택은 `event_id`, 0-based `choice_index`, `turn`, 실제 `actor_bindings`,
`receipt_type`, 고유 `receipt_id`, 원문 `document_ids`만 저장한다. 번역문, AP,
행동 카드, 수치 효과, 엔딩 결과를 이 영수증에 넣지 않는다. 첫 성공 쓰기는
write-once·idempotent이며 중복·역순·범위 밖 index·배우/문서 불일치·손상 저장은
새 사실을 발명하지 않고 닫힌다.

W209~W212는 기존 `arc_jaehyuk_mirror`와 별개의 두 번째 보증이 아니다. 아직
결정하지 않은 그 한 번을 확장·이동한 경로이며, W212의 거절·실제 서명·차단은
기존 완료/결과 플래그, 정신 비용, Moral Tint 변화와 `crossed_line` 흉터를 그대로
적용한다. 이 투자 세로줄이 열리지 않은 적격 후보에게는 W209부터 기존 짧은
보증 거울이 다시 열려 결정을 잃지 않게 한다.

같은 달의 순서는 단순 배열 순서가 아니다. M51은 검사 자료→민서의 비용 읽기→
다은과 목표 뒤 시간을 정하는 순서를, M53은 요청 PDF→통화→아버지 문서 비교→
다은에게 보여 줌→보증 결정을 지킨다. W210의 통화 뒤 문서 비교는 같은 주의
queue-only 전환이다. W216 빨간 원 사본은 `arc_sangchul_final_door` choice 0,
W220 자필 범위 원본은 `arc_y5_three_in_room_decision` choice 1만 읽는다.
고르지 않은 선택의 빨간 원·서명·차단·자필 동의를 추론하지 않는다.

영수증을 저장하는 것만으로 인과 연결을 완료했다고 보지 않는다. 47개 선택은
각각 이후 대사·가능성·비용·부재 또는 다음 경로의 실제 진입 가능성 중 적어도
하나를 바꾸는 이름 있는 reader를 가져야 한다. 단순 다음-root 순서 gate나 대화
로그는 choice-index reader가 아니다. 현재 M55 결정 3선택은 W221·W227의 정확한
문장을 바꾸고, 조건부 W220 영수증은 M56 진입 잠금의 실제 증거로 소비된다.

M49~M55 제품 원고는 후속 16루트의 `chapter5_causal_reads`를 reader 표면으로
쓴다. KO 정본은 `source_event_ids`, 그 부분집합인 `optional_source_event_ids`,
source별 choice-index 문장 배열 `texts`, `mode:"prepend"`를 소유하고, EN overlay는
같은 배열 모양의 `texts`만 번역한다. 런타임은 선행 영수증의 실제 choice index로
한 문장을 골라 본문 앞에 붙인다. 단순 선택명 요약이 아니라 전송 시각·빈 서명란·
접힌 병원 사본·차단된 입력창처럼 실제로 관찰된 행동을 읽어야 한다.

#### M56~M60 안전한 미실행 finale 영수증

`Chapter5FinaleRoute`는 `investment_safe_no_execution` 프로필 하나를 먼저
소유한다. M49~M55 경로가 실제 terminal 선택까지 끝났을 때만 W221 진입을
잠그며, M55 choice 1은 W220 자필 원본 receipt까지 있어야 한다. 진입에는 원본
경로·M55/W212/W215 선택, 아버지 생사와 마지막 연락 증거, 실제
`player/father/sangchul/daeun/minseo/jaehyuk` 배우를 저장한다. 이후 관계나
현재 상태가 바뀌어도 이미 잠근 출처·배우·생사를 다시 추론하지 않는다.

작성 원고는 생존·별세 변형을 포함한 11루트·30선택이고, 한 플레이는 둘 중
하나씩만 통과해 9루트·24선택이다. 단계는 `father_trace → custody → filing →
verdict → nontransaction → guarantee_return → father_answer → signature →
outbound` 순서로만 진행한다. 각 receipt는 root·주차·순서·배우·문서·선택 index를
write-once·idempotent로 저장하고, 중복·역순·범위 밖 선택·손상 저장은 새 사실을
발명하지 않고 경로를 닫는다. StoryMode는 선택 효과와 receipt를 한 묶음으로
적용하며 어느 한쪽이 실패하면 선택 전 전체 상태로 되돌린다.

M57 선택 0~3은 각각 `withdrawn`, `limited_filed`, `verification_hold`,
`self_filed`다. 붉은 철회 표지, 타인의 새 동의가 필요한 칸을 뺀 낮은 한도
접수본, 현재 동의 확인 보류와 임시번호, 자기 명의 227번은 서로 대체할 수
없으며 어느 것도 거래 실행이나 소유권을 뜻하지 않는다. M59는 아래 결과를
그대로 기록한다.

```json
{"kind":"none", "reason":"no_executable_contract",
 "cash_delta_krw":0, "asset_delta_krw":0, "debt_delta_krw":0}
```

W240에서는 마지막 서명 receipt가 먼저 완성되고 같은 밤 다은에게 보내는 행동이
뒤따른다. 둘째 선택까지 끝나면 ending 상태를 `pending → ready`로 바꾸고,
MainGame 복귀에서 먼저 `ready → consumed`를 한 번만 쓴 뒤 기존
`check_game_over()`에 넘긴다. 번아웃·정신 붕괴·채무·파산·중독의 즉시 실패는
이 보류보다 먼저 판정한다. 30억원 미달도 W240에서 기존 시간제 결말로 닫히며,
33세 첫 장의 30억원 `instant_legend` 이스터에그는 이 경로 진입 전이라 그대로다.
마지막 서명과 다은에게 보낸 밥 제안·사과·거리/다음 연락 시각은 능력치·경제·
숨은 도덕 수치나 옛 자기평가 flag로 바꾸지 않는다. 소비된 exact signature와
outbound receipt가 `사람들의 이후` 카드에서 실제 선택만 회수하고,
답장·용서·만남은 만들지 않는다.

#### 25억원 문턱·아버지 별세 일반 finale 영수증

`Chapter5FinaleRoute`의 두 번째 프로필 `general_near_goal_father_passed`는 기존
property 원장과 분리된 schema 1 `chapter5_general_finale_ledger.json`을 쓴다.
새 저장 필드를 추측해 채우지 않고, 다음 네 source 사건의 `event_id`·0-based
choice index·정확히 하나인 locale-neutral flag를 함께 확인한다.

| source | 선택 범위 | 마지막 독자 |
|---|---:|---|
| M51 `arc_minseo_03_arrival` | 0~1 | W229 색인, W237 봉인, W240 선발신 |
| M56 `arc_father_legacy` | 0~2 | W229 색인, W237 봉인, W240 선발신 |
| W229 `arc_y5_general_last_page_instruction` | 0~1 | W237 봉인, W240 서명 |
| M59 `arc_pre_ending_summit` | 0~1 | W237 봉인, W240 서명 |

투자·부동산 finale entry가 없고 아버지 별세가 고정됐으며 위 네 source가 하나씩
완전할 때만 W237에 진입한다. 원장은 `record_seal → signature → outbound` 3루트·
8선택을 W237, W240, 같은 W240 순서로 write-once 저장한다. W237 봉인 2선택은
색인과 매수인 이름이 빈 매물표의 앞뒤만 정하고, W240 서명 3선택은 확인된 사실·
이름과 시간·먼저 할 행동을 서로 다른 방식으로 해석한다. 이어지는 선발신 3선택은
민서 채널에 사실을 보내기, 아버지 기록 봉투에 한 줄을 남기기, 민서에게 구체적인
다음 주 시각을 묻기 중 민준이 실제로 한 행동 하나만 남긴다.

경로 정체성은 정상 writer가 만드는 두 형태만 허용한다. 아직 자각하지 않은
`none + tendency "" + route_invest false/없음`, 또는 부동산 원장이 잠기지 않은
`투자형 + tendency ""/invest + route_invest exact true`다. career/startup 이력이
true로 남았거나 경로 flag가 비-bool이거나 세 값이 서로 모순되면 W229와 W237 모두
기존 generic 흐름으로 fail-closed한다. entry가 한 번 잠긴 뒤에는 이후 정체성 변화로
원장 배우와 source를 다시 쓰지 않는다.

세 receipt의 `economic_outcome`은 비어 있다. 25억원대 매물표는 매매계약·이체·
등기·열쇠·부동산 소유권이 아니며, 민서의 읽음·답장·만남 수락과 떠난 아버지의
대답도 만들지 않는다. W237과 W240의 현재 방에는 민준 혼자 있고 두 사람은 연락
채널·봉투·기억으로만 읽힌다. outbound 뒤에만 `pending → ready`, MainGame
복귀에서 `ready → consumed`가 한 번 진행된 뒤 기존 엔딩 판정으로 넘어간다.

source 누락·복수 true·event log 불일치·생존 아버지·다른 일반 자산 구간은
빈 상태를 바꾸지 않고 기존 generic finale가 소유한다. 기존
`investment_safe_no_execution` 11루트·30선택/한 런 9·24, 즉시 실패 우선순위,
33세 Chapter 1의 30억원 `instant_legend`는 그대로다.

career/startup과 위 네 source가 불완전한 그 밖의 일반 안전 런은 어느 finale
프로필도 사실인 것처럼 바인딩하지 않는다.
기존 32루트·86선택은 계속 `reference_only`이며, 각 경제 경로의 실제 배우·문서·
물질 결과가 있는 별도 프로필이 생기기 전에는 제품 consumer를 붙이지 않는다.

## 9. 이관 순서

1. 24주 데모의 기존 영수증 구조를 공통 원장 후보로 삼고 저장 이관 규칙을
   설계한다. 현재 V2 영수증을 즉시 갈아엎지 않는다.
2. `M01 첫 선 → M35 선택을 들은 사람 → M55 같은 방의 세 사람` 세 단면으로
   입구·장간 회수·후반 인물 충돌을 먼저 증명한다.
3. 기존 240주 flag·deferred 후속을 생산자/독자/소비 상태로 장부화한다.
4. 미래 독자가 있는 소수의 결정과 기억만 선별해 옮긴다. 모든 선택을 영구화하지 않는다.
5. 다섯 장 보스와 엔딩 라우팅은 별도 배치로 이관하고, 기존 엔딩 ID·CG·저장
   호환을 보존한다.

자동 검사는 원장 완전성과 소비를 증명할 뿐, 작은 선택이 정말 기억나고 큰 선택이
정말 내 선택처럼 느껴지는지는 정상 속도 사람 플레이가 판정한다.

**구현 상태:** `story_map.json`의 M01~M60 장면 beat와 세 수직 단면은 작가용
배치 입력이다. 같은 파일의 월간 commitment·여유 계약은 사용자 NO-GO 뒤 제품
소비가 금지된 역사 자료다. W1~W24 V2의 저장과 첫 청구서 receipt는 이관 기준선으로
보존한다. M49~M55 기준 경로는 정확한 19루트·47선택의 직접 주차 ingress와
write-once 영수증 저장까지 제품에 연결됐다. 47선택 전부가 choice-index 대사,
조건부 증거 진입 또는 M56 경로 진입에서 실제로 소비된다. 그 뒤
`investment_safe_no_execution`은 11개 작성 변형·30선택, 한 플레이
9루트·24선택으로 W221~W240을 잇고, M59 경제 변화 0과 W240 두 장면 뒤 기존
엔딩 판정에 한 번만 넘긴다. 자동 검사는 인과·저장·결말 해제를 증명할 뿐 이
결말이 충분히 격동적이고 선택의 포기가 기억나는지는 정상 속도 사람 플레이가
판정한다. 첫 일반 프로필은 W229 2선택을 source로 더하고 W237/W240/W240의
별도 원장 3루트·8선택으로 네 source의 exact choice를 회수한다. 이 후보도
정상 속도 사람이 마지막 밤의 회수가 충분한지 판정하기 전에는 main 제품 완료로
승격하지 않는다. career/startup의 별도 32루트·86선택은 계속 reference-only다.
